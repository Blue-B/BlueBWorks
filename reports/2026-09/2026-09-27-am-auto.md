# 2026-09-27 오전 자동 회차

run_source: scheduled

## 프로젝트

InstallLens — npm `package-lock.json`을 설치 전에 오프라인으로 읽어 승인되지 않은 설치 스크립트, Git/원격 URL 의존성, 기본 레지스트리 항목의 integrity 누락을 검토하기 쉽게 정리하는 Python CLI.

## 선정 근거

후보는 세 가지를 짧게 비교했다.

1. **InstallLens** — npm v12가 2026-07-08 일반 공개되며 dependency install scripts, Git dependencies, remote URL dependencies를 기본 opt-in으로 바꿨다. 설치 전에 현재 lockfile의 검토 범위를 빠르게 보는 작은 도구로 범위를 제한할 수 있어 선택했다.
2. **MCP trust/capability map** — MCP 설정·권한 검토 수요는 있지만 기존 ScopeDiff와 주제 겹침이 커서 제외했다.
3. **브라우저 WebMCP 디버깅 보조 도구** — 최근 브라우저 변화와 연결되지만 특정 브라우저 실행·검증 범위가 커 이번 회차 완결성보다 불리해 제외했다.

확인한 공개 자료:
- GitHub Changelog, 2026-07-08: https://github.blog/changelog/2026-07-08-npm-install-time-security-and-gat-bypass2fa-deprecation/
- Checkmarx Zero, 2026-09-17: https://checkmarx.com/zero-post/npm-btree-malware-campaign-affects-millions-of-downloads-no-need-for-install-script/
- npm install 문서: https://docs.npmjs.com/cli/install/
- Socket: https://socket.dev/

대안과 차이:
- **npm 자체 install / approve-scripts 흐름**은 설치 정책을 실제 적용한다. InstallLens는 설치 전에 lockfile을 읽기 전용으로 요약하는 보조 도구다.
- **Socket**은 더 넓은 패키지 위협 인텔리전스·분석을 제공한다. InstallLens는 계정이나 업로드 없이 로컬 lockfile의 설치 정책 표면만 본다.

`python -m unittest -v test_installlens.py`에서 5개 테스트가 모두 통과했다. 검증한 내용은 승인되지 않은 install script 탐지, 정확한 버전 allowScripts 승인 처리, 명시적 거부 유지, 잘못된 lockfile 거부, `--strict` 종료 코드 2다.

테스트 입력에서 5개 패키지 중 직접 의존성 2개를 구분했고, 승인 전 install script 1개, Git 의존성 1개, 원격 URL 의존성 1개, integrity 누락 1개를 각각 탐지했다.

## 제한

이 결과는 악성 여부 판정이 아니다. 런타임 코드에 숨은 행위는 lockfile만으로 확인할 수 없고 사설 레지스트리 URL은 원격 URL로 표시될 수 있다. package-lock v2/v3의 `packages` 메타데이터가 필요하다. 미리보기는 비UI CLI의 검증된 출력 내용을 SVG로 재현한 것이며 화면 앱 캡처가 아니다.
