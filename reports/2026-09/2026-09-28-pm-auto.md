## 선택

후보 3개를 짧게 비교했다.

1. PyLockPeek — 표준 pylock.toml을 설치 없이 읽어 artifact 구성을 보여주는 도구. pip와 uv의 pylock 지원이 아직 실험/preview 성격을 갖고 있어 선택했다.
2. Core Metadata 2.6 Inspector — 2026년 5월 승인된 metadata 필드 검사기. wheel 추출까지 범위가 넓어 보류했다.
3. uv Config Precedence Map — 설정 우선순위 시각화. uv 자체 문서와 명령으로 확인 가능한 부분이 많아 보류했다.

근거:
- https://packaging.python.org/en/latest/specifications/pylock-toml/
- https://pip.pypa.io/en/stable/cli/pip_lock/
- https://docs.astral.sh/uv/concepts/preview/

대안:
- pip lock: 의존성을 해결해 pylock.toml을 생성한다. PyLockPeek은 기존 파일을 변경하지 않고 읽기만 한다.
- uv: pylock.toml 생성·설치를 지원한다. PyLockPeek은 Python 표준 라이브러리만으로 artifact 구성을 훑는다.

## 구현

`projects/pylockpeek/`에 Python 3.11+ CLI를 구현했다. lock-version, created-by와 패키지별 wheel/sdist/VCS/directory/archive 기록을 읽고 wheel 없이 sdist만 기록된 패키지를 `--source-only`로 필터링한다. `--json` 출력도 지원한다.

## 검증

ChatGPT 작업 컨테이너에서 GitHub Actions 없이 직접 검증했다.

- 단위 테스트 5개 통과: 패키지 수, artifact 분류, source-only 필터, 잘못된 lock-version과 package name 오류를 확인했다.
- 합성 `examples/pylock.toml`을 실제 실행해 3개 패키지와 sdist-only 1개가 표시되는 것을 확인했다.
- `--source-only` 실행에서 native-ext 한 항목만 남는 것을 확인했다.
- Python 문법 검사도 통과했다.
- 저장소 project.json 검사와 등록된 test/smoke 실행을 통과했다.
- GitHub Actions는 사용하지 않았다.

## 제한

환경 마커 평가나 실제 설치·빌드는 하지 않는다. sdist-only 표시는 설치 실패 판정이 아니라 lock 파일에 기록된 artifact 종류를 보여주는 정보다.
