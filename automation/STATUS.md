## 실제로 통과한 검사

임시 격리 실행 환경의 Python 3.13.5에서 다음 명령을 실행했다.

```sh
python3 -I -S -m unittest discover -s tests -v
python3 -I -S automation/check.py
python3 -I -S automation/check.py --run
```

검증기 회귀 테스트 26개가 모두 통과했다. 누락된 실제 소스·테스트, 잘못된 날짜·출처 형식, 경로 이탈·외부 심볼릭 링크, 중복 출처, 잘못된 명령 배열·시간 제한 등을 거부했고, 실제 명령 실행·실패·시간 초과 전달을 확인했다.

검사한 두 파일은 GitHub 커밋의 파일과 Git blob SHA가 일치한다.

| 파일 | Git blob SHA |
| --- | --- |
| automation/check.py | 9b4a0d7ec690671427b60733ddfd015ba62e293a |
| tests/test_check.py | 80b77c7238f858e27f64fce8da404179738e26d5 |

프로젝트가 아직 없으므로 등록 검사와 `--run`은 제품을 검증했다고 주장하지 않고 빈 저장소 상태를 명시했다. **이 26개 테스트는 운영 기반의 테스트이지 제품 26개 또는 제품 기능 검증이 아니다.**

## 아직 해결·검증되지 않은 부분

[GitHub Actions 최초 실행](https://github.com/Blue-B/BlueBWorks/actions/runs/36190045490)은 실패했다. job `108252722158`에는 실행된 단계가 없고 runner가 할당되지 않은 상태로 종료됐다. 작업 로그 조회는 `BlobNotFound`를 반환했으며, 현재 연결 도구에서 추가 오류 주석을 읽을 수 없어 정확한 원인은 확인하지 못했다. 코드 테스트가 실패했다거나 결제·사용량 제한 때문이라고 추정해 단정하지 않는다. 결제 설정, 권한, 저장소 공개 범위는 변경하지 않았다.

연결된 원격 개발 도구에서도 호출 인자 호환 오류가 확인됐다. 그래서 이번 검증은 임시 격리 실행 환경에서 수행했다. 다음 회차도 원격 도구가 안 되면 사용 가능한 임시 실행 환경에 GitHub에서 읽은 정확한 파일을 복원하여 검사할 수 있다. 임의의 다른 버전을 검사하고 원격 커밋이 통과했다고 말하지 않는다. 네트워크 clone이 불가능해도 GitHub 연결의 파일 읽기 경로는 별도로 사용할 수 있다.

예약 등록, 수동 GitHub 쓰기, 격리 환경 테스트 성공과 **실제 예약 회차의 무인 개발 성공은 별개**다. 첫 무인 회차는 아직 실행·검증되지 않았다. 아직 신규 제품은 0개이며, 운영 설정을 일일 제품 두 개에 포함하지 않는다.
