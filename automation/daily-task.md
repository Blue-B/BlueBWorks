# 매 회차 절차

1. 실제 Asia/Seoul 날짜·시간을 확인한다. 예약 오전 회차는 am, 저녁 회차는 pm이다. 현재 실행이 13시 이전이면 am, 이후면 pm으로 해석한다. 재개 요청은 기존 회차 식별자를 보존한다.
2. 기본 브랜치, AGENTS.md, 최근 프로젝트, 모든 상태의 최근 daily PR, 해당 회차 브랜치·보고서를 읽는다. 기존 완료 회차는 중복 생성하지 않는다.
3. 최신 공개 정보로 후보 세 개 이상을 비교한다. 최신 기술 이름을 억지로 넣지 않는다. 제품의 실제 쓰임새와 기존 대안 두 개 이상과의 차이로 하나를 고른다. 공식 출처를 포함해 서로 다른 URL 두 개 이상과 확인일을 기록한다.
4. 독립 실행 가능한 핵심 기능을 실제 구현한다. 사용자 입력, 정상 동작, 잘못된 입력, 빈 상태, 필요한 경우 모바일 레이아웃까지 처리한다. 가짜 연동·허위 수치·데모 전용 데이터만으로 완성했다고 하지 않는다.
5. `projects/<slug>/project.json`을 실제 조사·코드 내용에 맞춰 작성한다. README에는 용도, 설치·실행, 예제, 테스트, 비용·데이터 처리, 한계, 비교와 출처를 포함한다.
6. 저장소 검사와 프로젝트 실제 테스트·필요한 빌드를 실행한다. GitHub 연결만 쓸 수 있으면 작업 브랜치에 코드와 검사 설정을 반영한 뒤 Actions의 실제 결과를 확인한다. 실행 도구가 없거나 승인 대기로 막히면 그 사실을 보고한다.
7. 회차 브랜치와 PR에 결과를 남긴다. 기본 브랜치 자동 병합은 하지 않는다. 유료 호출·배포·홍보·계정 생성·다른 저장소 변경도 하지 않는다.
8. 회차 보고서에 선정 근거, 대안 비교, 구현 내용, 실제 확인된 검사, 커밋·PR·검사 링크, 실행 방법과 한계를 기록한다. 아직 모르는 커밋이나 검사 링크는 지어내지 않는다. 코드 커밋을 검증한 뒤 문서에 그 코드 커밋을 인용할 수 있다.
9. 사용자에게 사람이 이해할 수 있는 한국어로 결과를 보고한다. 미완성·실패는 신규 프로젝트 완료 개수에서 제외한다. 두 개 목표를 맞추려고 저품질 프로젝트를 추가하거나 기존 프로젝트 수정·문서 작업을 신규 프로젝트로 세지 않는다.
