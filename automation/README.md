# 예약 실행과 검증

## 역할 분리

ChatGPT 예약 작업이 조사·주제 선정·개발 도구 호출·보고를 시작한다. 한국시간 오전 8시·오후 7시 전후에 각 한 프로젝트를 목표로 하며, 처리 완료 시간이 고정되는 것은 아니다. 예약은 ChatGPT에서 관리한다. 별도 LLM API 키나 서버 cron은 이 구성에서 만들지 않는다.

GitHub MCP는 저장소 읽기와 브랜치·코드·PR 반영 및 검증된 PR의 main 병합에 사용한다. 실행 환경이 사용 가능하면 그곳에서 검사하고, GitHub Actions의 같은 커밋 검사 결과를 별도로 확인한다. GitHub Actions의 `verify.yml` 자체에는 AI 모델 호출이나 개발 예약이 없다. clone/fork만으로 개발 자동화가 복제되는 것도 아니다.

연결 앱의 권한 또는 승인 요구 때문에 예약이 멈출 수 있다. 실제 첫 무인 개발 회차는 아직 검증되지 않았다. 수동으로 저장소 생성·코드 검증·main 반영이 성공해도 그것을 무인 개발 성공으로 표시하지 않는다.

## 상태와 중복 방지

회차 식별자는 한국 날짜와 `am|pm`이다. 브랜치 `daily/YYYY-MM-DD-am|pm`과 해당 보고서의 기존 상태를 먼저 확인한다. 완료된 회차를 다시 만들지 않고, 실패·중단한 회차는 같은 브랜치에서 재개한다. 오전·저녁 결과는 서로 다른 프로젝트여야 한다. 미병합 PR도 확인해 동일한 아이디어를 반복하지 않는다.

소유자는 검증한 결과의 **비공개 main 자동 반영**을 승인했다. 작업 브랜치에 push하고 PR을 만든 뒤 검증 조건을 만족하면 main으로 실제 병합한다. PR 생성 또는 병합 예약만으로 끝내지 않는다. 반영 후 원격 main의 커밋과 프로젝트 소스·보고서를 다시 읽어 실제 반영을 확인한다. main에 없으면 전체 작업은 미완료다. 과거 상태 기록과 보고서의 '기본 브랜치 병합 금지'는 이전 운영 방식이다.

각 프로젝트는 독립 폴더, 각 보고서는 회차별 파일을 사용해 불필요한 병합 충돌을 줄인다. 병합 직전 원격 최신 상태를 확인하고 다른 작업과 사용자의 변경을 보존한다.

## 프로젝트 등록 형식

`projects/<slug>/project.json`에 이름, 설명, 문제, 대상 사용자, 현재 관련성, 차별점, 수익화 가설, 한계, 소스 파일·테스트 파일, 설치·검사 명령, 조사 출처와 기존 대안을 기록한다. `project.template.json`은 제품이 아닌 양식이다. 출처 `checked_at`과 프로젝트 `created_at`은 `YYYY-MM-DD`, 출처 `published_at`은 확인된 경우만 같은 형식으로 넣는다.

`setup`과 `checks`의 명령은 문자열 하나가 아니라 인자 배열이다. 프로젝트 폴더에서 `shell=False`로 실행된다. 예: `["python3", "-m", "unittest", "discover", "-s", "tests", "-v"]`. `checks`에는 적어도 `kind: "test"` 하나가 있어야 한다. 필요한 경우 `build`, `smoke` 검사도 추가한다. 각 명령의 제한 시간은 1~300초다. runner에 없는 언어 환경이 필요하면 승인 범위 안에서 환경을 구성하고 검증한다. 유료 사용을 무단 활성화하지 않는다.

구조 검사기는 소스·테스트 파일 존재, 경로 이탈, 중복 이름, 출처·대안 누락, 잘못된 명령 형식을 검출한다. URL이 살아 있는지나 비교 주장이 맞는지, 테스트가 충분한지는 개발 회차에서 별도로 확인해야 한다.

## 검증과 차단 조건

실제 코드 테스트나 빌드가 실패하면 수정·재검증 전 main에 넣지 않는다. 실행 검증이 없으면 성공을 주장하지 않는다. 필수 검사·리뷰·보호 규칙·앱 승인이 막으면 우회하지 않고 정확한 단계와 남은 작업을 보고한다.

원격 CI가 runner 미할당 또는 steps 없음 등으로 테스트를 시작하지 못했더라도, 정확히 같은 소스의 직접 실행 테스트·빌드가 정상이고 필수 검사·보호 규칙이 막지 않으면 비공개 프로토타입을 main에 반영할 수 있다. 이 경우 직접 검증과 원격 CI 실패·미실행을 분리해 기록한다. 코드 테스트 실패나 원인이 불명확한 실패를 이 예외로 바꾸지 않는다. 로그 근거 없이 과금·한도·권한 탓이라고 단정하지 않는다.

## 복구와 중지

예약 중지: ChatGPT 예약 작업 관리에서 `BlueBWorks 하루 두 작품`을 일시 중지한다. 저장소 파일을 삭제할 필요가 없다. 이미 만들어진 코드·PR은 자동으로 삭제되지 않는다.

실행 장애: 보고서에 실패한 단계와 원인을 남긴다. main 반영까지 완료되지 않았다면 완료 개수에 넣지 않는다. 앱 접근이나 승인이 필요한 상황을 우회하지 않는다. 검증된 결과만 main에 반영하며 실패한 코드나 미검증 산출물은 작업 브랜치에 보존한다.

저장소는 private으로 유지한다. 공개 전환, 외부 배포·릴리즈, 과금·권한·보호 규칙 변경은 별도 승인 없이는 하지 않는다. 전체 승인 범위는 루트 AGENTS.md를 따른다.
