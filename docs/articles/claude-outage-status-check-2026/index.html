11월 13일 저녁 클로드 로그인 장애 흐름

11월 13일 금요일 저녁, 클로드에 로그인이 안 된다는 이야기가 한꺼번에 쏟아졌습니다. Anthropic 상태 페이지 status.claude.com에 첫 공지가 뜬 시각은 한국 시간 18시 58분입니다. 공지 문장은 "users authenticating to Claude.ai and Claude Code"로, claude.ai 웹과 클로드 코드에 로그인하는 단계에서 오류가 난다는 내용이었습니다.

첫 공지와 함께 서비스별 상태도 바뀌었습니다. claude.ai는 Major Outage, 개발자 콘솔(platform.claude.com)과 클로드 코드는 Partial Outage, 클로드 코워크는 Degraded Performance로 표시됐습니다. API(api.anthropic.com)는 이 공지의 영향 목록에 들어 있지 않았습니다. 앱 로그인이 막혀도 API 키로 붙는 서비스는 영향을 덜 받았을 수 있다는 뜻입니다.

20시 05분에는 수정이 배포돼 회복을 지켜보는 Monitoring 단계로 넘어갔고, 20시 58분에 claude.ai와 클로드 코워크 문제가 해결됐다는 Resolved 공지가 올라왔습니다. 첫 공지부터 해결까지 정확히 2시간입니다. 해커뉴스 첫 페이지에도 이 공지 링크가 올라와 21시 무렵 241점, 댓글 174개가 붙어 있었습니다.

공지 세 개 어디에도 원인 설명이나 사용량 보상 이야기는 없습니다. 검색창에 클로드 장애 보상을 치는 사람이 많은데, 지금까지 나온 공식 문장만 보면 보상 안내는 없는 상태입니다.

status.claude.com 서비스별 상태 읽는 법

클로드가 이상하면 제일 먼저 열 곳이 status.claude.com입니다. 로그인 없이 열리고, 맨 위에는 진행 중인 장애 공지가, 그 아래에는 서비스별 칸이 나옵니다. 칸은 claude.ai(웹과 앱), Claude Console, Claude API, Claude Code, Claude Cowork, 정부용, 클라우드 플랫폼용으로 나뉩니다.

칸마다 막대가 하루에 하나씩, 30일 치가 붙어 있습니다. 초록은 별일 없던 날이고 노랑, 주황, 빨강으로 갈수록 그날 장애가 컸다는 뜻입니다. 막대 아래 숫자는 최근 30일 가동률입니다. 21시 17분에 열었을 때 claude.ai 99.57%, 콘솔 99.95%, API 99.88%, 클로드 코드 99.83%, 코워크 99.87%였습니다. 같은 클로드라도 웹 앱 쪽 숫자가 가장 낮습니다.

오늘 열어 보며 눈에 띈 게 하나 있습니다. 20시 58분에 해결 공지가 올라왔는데, 21시 17분에 다시 열어도 claude.ai 칸은 여전히 빨간 Major Outage였습니다. 해결 공지에는 서비스 상태를 바꾸는 항목이 없었고, 그 직전 Monitoring 공지가 claude.ai를 Major Outage로 둔 채 끝났습니다. 여기에 11월 13일 새벽 2시 52분에 올라온 마이크로소프트 365 커넥터 장애 공지가 아직 열려 있고, 이 공지도 claude.ai와 코워크를 영향 대상으로 잡고 있습니다.

그래서 빨간 글자만 보고 클로드 전체가 아직 안 된다고 판단하면 틀릴 수 있습니다. 칸 색과 함께 맨 위 공지 제목을 같이 읽어야 합니다. 제목에 Microsoft 365 connector가 있으면 아웃룩 메일, 일정, 검색 연결이 문제라는 뜻이고 일반 대화와는 거리가 멉니다. 반대로 칸이 모두 초록인데 나만 안 된다면 장애보다는 내 계정이나 네트워크 쪽을 먼저 보는 편이 빠릅니다.

오류 코드로 장애와 내 한도 구분하기

API를 쓰거나 클로드 코드를 터미널에서 돌리면 오류가 숫자로 나옵니다. 이 숫자만 봐도 서버 문제인지 내 쪽 문제인지 꽤 갈립니다. Anthropic API 문서에 적힌 것 중 자주 보는 네 가지를 표로 묶었습니다.

529는 Anthropic 쪽이 붐빈다는 뜻이라 내가 고칠 수 있는 게 없습니다. 공식 SDK는 연결 오류, 한도 초과, 5xx 서버 오류를 기본 두 번까지 간격을 늘려 가며 다시 보내고, 응답에 retry-after 헤더가 있으면 그 시간을 지킵니다. 그래도 계속 실패하면 그때 상태 페이지를 엽니다. 500도 서버 쪽 오류인데, 계속되면 응답에 붙은 request ID를 들고 지원팀에 문의하라고 안내합니다.

429는 성격이 다릅니다. 조직의 속도 한도에 걸렸거나, 사용 등급의 월 지출 상한에 닿았거나, 클로드 코드 워크스페이스의 지출 한도에 닿았을 때 나옵니다. 지출 상한 때문에 나온 429에는 retry-after 헤더가 없고 다시 쓸 수 있을 때까지 계속 실패합니다. 사용량이 갑자기 크게 늘면 한도 아래에서도 429가 날 수 있다고 적혀 있습니다. 상태 페이지는 멀쩡한데 429만 계속 나온다면 내 한도 문제로 보면 됩니다.

헷갈리기 쉬운 경우가 하나 더 있습니다. 조직이나 워크스페이스에 내가 직접 정해 둔 지출 한도에 닿으면 429가 아니라 400 invalid_request_error가 돌아옵니다. 요청 형식이 틀렸을 때와 같은 코드라 처음 보면 내 코드가 고장 난 줄 알기 쉽습니다. 메시지에 한도 이야기가 들어 있는지 먼저 읽어 보고, 맞다면 콘솔에서 내가 정한 한도를 고쳐야 풀립니다. 클로드 코드 워크스페이스의 한도만은 예외로 429가 나온다고 문서에 따로 적혀 있습니다.

claude.ai 웹과 앱은 숫자 대신 안내 문장으로 보여 줍니다. 대화 한도에 걸린 것인지는 설정의 사용량 화면에서 남은 양으로 가늠할 수 있습니다. 오늘처럼 로그인 화면에서 막히는데 사용량은 남아 있다면, 상태 페이지 공지부터 보는 게 순서입니다.

터미널에서 클로드 상태 한 줄로 보기

status.claude.com은 아틀라시안 Statuspage로 만든 페이지라 공개 API가 같이 열려 있습니다. 키나 로그인 없이 주소만 부르면 상태가 JSON으로 돌아옵니다. 쓸 만한 주소는 세 개입니다. /api/v2/status.json은 전체 요약, /api/v2/components.json은 서비스별 상태, /api/v2/incidents/unresolved.json은 아직 끝나지 않은 공지 목록입니다.

윈도우 PowerShell에서 직접 불러 봤습니다. 21시 17분 결과는 전체 요약이 major, Partial System Outage였고 서비스별로는 claude.ai만 major_outage, 코워크가 degraded_performance, 나머지는 operational이었습니다. 웹 화면에서 본 값과 같습니다. 끝나지 않은 공지 목록에는 마이크로소프트 365 커넥터 건 하나만 남아 있었습니다. 맥이나 리눅스라면 curl로 같은 주소를 부르면 됩니다.

전체 요약 값은 오늘처럼 커넥터 하나 때문에도 major가 될 수 있어서, 실제로 쓸모 있는 건 components.json에서 내가 쓰는 서비스 한 줄입니다. 클로드 코드만 쓴다면 Claude Code 줄이 operational인지만 보면 되고, 작업을 돌리기 전에 이 한 줄을 먼저 부르는 짧은 스크립트를 만들어 둘 수도 있습니다.

JSON 도구가 따로 없는 맥이나 리눅스에서도 grep 하나로 원하는 줄만 뽑을 수 있습니다. 응답 안에서 서비스 이름 바로 뒤에 상태 값이 붙어 나오기 때문입니다. 같은 시각에 돌려 보니 Claude Code는 operational, claude.ai는 major_outage가 찍혔습니다. 이 결과를 셸 스크립트 맨 앞에 두고 operational이 아닐 때만 경고를 띄우게 하면, 긴 작업을 걸어 놓고 한참 뒤에야 실패를 알아채는 일을 줄일 수 있습니다.

클로드 장애 알림 받는 방법

매번 페이지를 열 필요는 없습니다. 오른쪽 위 Subscribe to Updates 버튼을 누르면 알림 받는 방법이 아이콘으로 나옵니다. 이메일, 문자(SMS), 슬랙, 마이크로소프트 팀즈, 웹훅, 고객지원 문의, RSS 순서입니다. 이메일을 고르면 장애 공지가 새로 생기거나, 바뀌거나, 해결될 때마다 메일이 옵니다.

혼자 쓴다면 RSS가 가장 가볍습니다. 주소는 https://status.claude.com/history.rss이고 아톰 형식은 history.atom입니다. 쓰고 있는 RSS 리더에 넣어 두면 새 공지가 바로 보이고, 이메일이나 전화번호를 넘기지 않아도 됩니다. 팀이 같이 쓴다면 슬랙이나 팀즈 채널로 받는 쪽이 편합니다. 누가 클로드 지금 되냐고 묻기 전에 채널에 공지가 먼저 올라옵니다.

진행 중인 공지 하나만 따라가고 싶다면 공지 제목 옆 Subscribe 버튼을 쓰면 됩니다. 오늘 같은 두 시간짜리 장애를 지켜볼 때 알맞습니다.

최근 30일 클로드 장애 기록

상태 페이지 공지 기록을 API로 받아 10월 14일부터 11월 13일까지 30일을 세어 봤습니다. 공지는 15건이었습니다. 영향도로 나누면 critical 1건, major 8건, minor 5건, none 1건입니다. 대략 이틀에 한 번꼴로 무언가 공지가 올라온 셈입니다. claude.ai의 30일 가동률 99.57%를 단순 계산하면 30일 가운데 3시간 남짓이 문제가 있던 시간에 해당합니다.

10월 24일부터 28일 사이에는 특정 모델 오류 공지가 몰렸습니다. 제목에 Sonnet 5.5, Fable 5.1, Opus 5.5 같은 모델 이름이 들어간 공지가 7건이었고, 이 공지들은 claude.ai, API, 클로드 코드, 코워크를 모두 영향 대상으로 잡았습니다. 7건 중 6건은 한 시간 안에 끝났고, 가장 길었던 건 10월 25일 Sonnet 5.5 오류로 99분이었습니다.

커넥터 장애는 결이 다릅니다. 10월 22일 커넥터 전반(257분), 10월 28일 Gmail(109분), 10월 29일 구글 캘린더(226분) 공지는 대화 자체보다 외부 서비스 연결이 막힌 경우였고 시간이 길었습니다. 11월 13일 새벽에 시작된 마이크로소프트 365 커넥터 건은 Anthropic이 마이크로소프트 쪽 장애가 원인이라고 밝혔고, 이 글을 쓰는 시점에도 끝나지 않았습니다.

11월 13일 하루만 놓고 보면 공지 두 건이 겹쳤습니다. 새벽 2시 52분에 시작된 마이크로소프트 365 커넥터 장애가 끝나지 않은 상태에서 저녁 18시 58분에 로그인 장애가 새로 올라왔고, 두 공지 모두 claude.ai를 영향 대상으로 잡았습니다. 아침부터 아웃룩 연결이 안 되던 사람이라면 저녁 로그인 오류까지 하루 종일 같은 장애로 느꼈을 수 있지만, 공지로 보면 따로 올라온 두 건입니다. 그래서 상태 페이지를 볼 때는 빨간 칸 하나보다 그 칸을 빨겛게 만든 공지가 몇 개인지부터 세어 보는 게 좋습니다.

쓰는 입장에서 정리하면 이렇습니다. 공지 제목에 모델 이름이 있으면 다른 모델로 바꿔 보는 게 가장 빠른 우회로이고, 커넥터 이름이 있으면 그 연결만 잠시 빼고 쓰면 됩니다. 오늘 같은 로그인 장애는 기다리는 것 말고 할 게 없으니 RSS나 메일 알림을 걸어 두고 해결 공지를 기다리는 편이 덜 지칩니다. 업무에 급하게 써야 한다면 영향 목록에 잘 안 들어가는 다른 경로, 예를 들어 클라우드 플랫폼을 거치는 API 하나쯤 미리 열어 두는 것도 방법입니다.
