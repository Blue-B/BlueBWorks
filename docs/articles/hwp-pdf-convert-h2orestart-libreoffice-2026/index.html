HWP PDF 변환, 한글 프로그램 없이 하는 방법

관공서 공지, 학교 가정통신문, 입찰 서류는 아직도 HWP나 HWPX로 많이 옵니다. 한컴오피스가 없는 맥이나 리눅스, 회사 PC에서는 파일을 열지 못해 PDF로 바꿔 줄 곳부터 찾게 됩니다. 검색하면 파일을 올리는 변환 사이트가 먼저 나오지만, 주민등록번호나 연락처가 든 서류를 남의 서버에 올리기는 아무래도 꺼려집니다.

H2Orestart는 이럴 때 쓸 수 있는 리브레오피스 확장입니다. 개발자 ebandal이 만든 오픈소스로, 리브레오피스가 HWP와 HWPX 파일을 열 수 있게 해 줍니다. 확장 사용은 무료이고 소스코드는 GNU GPLv3로 공개돼 있으며, 2026년 10월 18일에 0.8.0이 나왔습니다.

확장을 넣은 리브레오피스는 한글 파일을 일반 문서처럼 열고, 명령 한 줄로 여러 파일을 PDF로 만들 수 있습니다. 파일이 내 컴퓨터 밖으로 나가지 않는다는 점이 업로드형 변환 사이트와 가장 큰 차이입니다. 다만 한컴오피스와 똑같이 그려 주는 것은 아니어서, 정부 부처가 HWP와 PDF를 함께 올린 보도자료 4개를 직접 바꿔 원본 PDF와 나란히 놓고 어디가 달라지는지 살펴봤습니다.

H2Orestart 설치 방법: 리브레오피스 확장 관리자에 추가

준비물은 리브레오피스와 자바입니다. 리브레오피스 확장 사이트의 H2Orestart 페이지에는 JRE 8 이상이 필요하다고 적혀 있고, 자바가 없으면 확장이 동작하지 않습니다. 윈도우와 맥이라면 리브레오피스 위키의 자바 설치 안내를 먼저 따라 하면 됩니다.

확장 파일은 GitHub 릴리스나 리브레오피스 확장 사이트에서 H2Orestart.oxt로 받습니다. 리브레오피스를 연 뒤 도구 메뉴의 확장 관리자에서 추가를 눌러 이 파일을 고르고 리브레오피스를 다시 시작하면 됩니다. 그다음부터는 파일 열기 창에서 한글 파일을 고르거나 창에 끌어다 놓으면 열립니다. 열린 문서를 다시 저장할 때는 HWP가 아니라 ODT 형식으로만 저장되니, 원본 한글 파일은 따로 남겨 두는 게 좋습니다.

리눅스는 명령으로 넣는 쪽이 빠릅니다. 우분투와 데비안 저장소에도 libreoffice-h2orestart 패키지가 있지만, 우분투 24.04 저장소에 올라 있는 판은 0.6.1이라 최신 0.8.0과 차이가 큽니다. 0.8.0에서 표 행이 잘리던 문제와 체크박스 기호가 빈 상자로 나오던 문제가 고쳐졌으니 릴리스의 oxt 파일을 직접 넣는 편을 권합니다. 아래는 우분투 24.04에서 실제로 넣은 순서입니다.

한글 파일을 고쳐 써야 한다면 PDF 대신 ODT로 바꾸면 됩니다. 아래 변환 명령에서 --convert-to 뒤를 odt로 바꾸면 리브레오피스 문서 파일이 나오고, 국토부 HWPX 파일 하나가 15초 만에 ODT가 됐습니다. ODT는 리브레오피스에서 열어 고친 뒤 파일 메뉴의 PDF로 내보내기로 다시 PDF를 만들 수 있습니다.

한글 파일 PDF 일괄 변환 명령과 걸린 시간

확장을 넣으면 리브레오피스를 화면 없이 띄우는 headless 모드로 한글 파일을 PDF로 바꿀 수 있습니다. README에 나온 방법은 두 가지입니다. --infilter로 H2Orestart 필터를 직접 지정하는 방법과, 필터를 빼고 리브레오피스가 파일을 보고 알아서 고르게 두는 방법입니다. 윈도우에서는 soffice 자리에 리브레오피스 설치 폴더의 program 안에 있는 soffice.exe를 쓰면 됩니다.

11월 12일 정책브리핑에 올라온 보도자료 4개(HWPX 3개, HWP 1개)를 한 폴더에 넣고 두 번째 방식으로 한꺼번에 돌렸습니다. 리브레오피스 24.2.7과 H2Orestart 0.8.0 조합에서 4개 모두 PDF가 됐고, 걸린 시간은 22.1초였습니다.

파일마다 명령을 따로 돌리면 리브레오피스를 매번 새로 띄우느라 한 개에 16초에서 36초가 걸렸습니다. 여러 개를 바꿀 때는 파일 이름을 한 줄에 몰아 넘기는 편이 훨씬 빠릅니다.

만들어진 PDF에는 글자가 그림이 아니라 글자로 들어갑니다. 변환한 국민통합위원회 보도자료 PDF에서 글자를 뽑아 보면 '국민통합'이 20번 나옵니다. PDF 안에서 찾기를 쓰거나 문장을 복사해 다른 문서에 붙여야 할 때 이 차이가 큽니다.

HWP PDF 변환 결과 비교: 글꼴과 쪽수가 달라지는 곳

국토교통부의 진에어, 에어서울, 에어부산 합병 인가 보도참고자료를 부처가 올린 PDF와 나란히 놓으면 제목 상자, 굵은 강조, 각주 기호까지 자리가 그대로입니다. 눈에 띄는 차이는 글꼴입니다. 원본은 함초롬바탕, 굴림, 맑은 고딕 같은 글꼴을 쓰는데 변환한 컴퓨터에는 함초롬 글꼴이 없어서 나눔고딕과 노토 산스 CJK로 바뀌었습니다.

글꼴이 바뀌면 줄 간격도 조금씩 넓어집니다. 이 문서는 원본이 3쪽인데 변환본은 4쪽이 됐고, 늘어난 마지막 쪽에는 쪽 번호만 남았습니다. 윈도우에 들어 있는 굴림, 바탕, 맑은 고딕 글꼴을 옮겨 넣고 다시 바꿔도 쪽수는 그대로였으니, 원본이 주로 쓴 함초롬 글꼴까지 있어야 원본에 더 가까워질 것으로 보입니다.

글자가 빠지지 않았는지도 세어 봤습니다. 두 PDF에서 글자를 뽑아 공백을 빼고 세면 국토부 문서는 1,623자와 1,618자, 국토부와 공정위 공동 자료는 1,545자와 1,541자, 국민통합위원회 문서는 1,332자로 똑같았습니다. 몇 글자 차이는 원본의 '- 1 -' 같은 쪽 번호가 변환본에서 숫자만 남은 탓이라, 본문에서 사라진 글자는 없었습니다.

그림과 로고가 많은 한글 문서에서 생긴 차이

차이가 더 크게 난 곳은 그림이 많은 문서였습니다. 고병원성 조류인플루엔자 중앙사고수습본부 보도자료는 1쪽 맨 아래의 기관 로고 줄이 다음 쪽으로 밀려 혼자 한 쪽을 차지했고, 붙임 포스터 뒤에 빈 쪽이 하나 더 생겨 2쪽짜리가 4쪽이 됐습니다. 포스터 이미지 자체는 깨지지 않고 그대로 들어갔습니다.

HWP 형식인 국민통합위원회 보도자료는 본문 글자, 화살표, 표 모양은 멀쩡했지만 맨 위 기관 로고의 윗부분이 잘린 채 나왔습니다. 원본은 명조 계열 글꼴인데 변환본은 고딕 계열로 바뀌어 인상도 꽤 달라 보입니다.

네 문서를 정리하면 아래와 같습니다. 내용을 읽고 보관하거나 인쇄해서 보는 데는 충분했습니다. 원본과 같은 쪽수와 모양이 꼭 필요한 제출 서류라면 한컴오피스에서 저장한 PDF를 받거나, 변환본을 한 쪽씩 넘겨 보고 빈 쪽을 지운 뒤 쓰는 편이 안전합니다.

브라우저에서 바로 HWP를 PDF로 바꾸는 방법과 차이

설치가 번거롭다면 브라우저 안에서 한글 파일을 그려 주는 도구도 있습니다. 더쿼카스튜디오의 HWP, HWPX PDF 변환 페이지는 오픈소스 rhwp(MIT 라이선스)를 웹어셈블리로 돌려 파일을 서버로 보내지 않고 브라우저 안에서 읽는다고 안내합니다. 같은 국민통합위원회 HWP 파일을 넣으니 2쪽으로 열렸고, H2Orestart 변환본에서 잘렸던 맨 위 로고도 제대로 그려졌습니다.

대신 이 페이지에서 저장한 PDF는 쪽마다 약 192dpi 그림으로 담깁니다. 그래서 PDF 안에서 글자를 고르거나 찾을 수 없고, 글자가 필요하면 '글자만 저장(TXT)'으로 따로 받아야 합니다. 열어 보기와 PDF, TXT 저장은 무료이고 여러 파일을 한 번에 바꾸는 기능과 표를 엑셀로 받는 기능은 아직 판매 전인 이용권으로 열릴 예정이라고 합니다. 암호가 걸린 문서는 아직 열지 못합니다.

고르는 기준은 간단합니다. 파일 하나를 빨리 열어 보고 넘길 거라면 브라우저 도구가 편하고, 여러 개를 한꺼번에 바꾸거나 글자 검색이 되는 PDF가 필요하면 H2Orestart가 맞습니다. 원본 글꼴이 없는 컴퓨터에서는 둘 다 줄바꿈이 원본과 조금 다를 수 있다는 점은 같습니다.

주민등록번호가 든 신청서나 계약서처럼 민감한 서류는 파일을 올리는 변환 사이트보다 이 두 방법 중 하나를 쓰는 편이 마음 편합니다. H2Orestart는 처음부터 끝까지 내 컴퓨터 안에서 돌고, 브라우저 도구도 안내대로라면 파일이 브라우저 밖으로 나가지 않습니다.

H2Orestart 변환이 깨질 때 로그 보는 법

파일이 열리지 않거나 모양이 크게 틀리면 H2Orestart가 남기는 로그부터 보면 됩니다. 리눅스는 ~/.cache/H2Orestart/, 맥은 ~/Library/Caches/H2Orestart/, 윈도우는 사용자 폴더 아래 .H2Orestart 폴더에 쌓입니다. 개발자는 이 폴더를 통째로 압축하고 원본 한글 파일을 붙여 GitHub 이슈로 올려 달라고 안내합니다.

이때 로그에 문서 내용 일부가 남을 수 있다는 점을 README가 따로 적어 두었습니다. 개인정보가 든 서류라면 로그와 원본에서 그 부분을 지운 뒤 올려야 합니다.

릴리스 기록을 보면 배포용 문서 열기(0.7.11), 옛한글 한양 PUA 코드 변환(0.7.12)처럼 제보를 받아 기능을 늘려 왔습니다. 옛한글이 든 문서는 노토 산스 CJK처럼 옛한글을 표준 유니코드로 그리는 글꼴이 깔려 있어야 제대로 보입니다.
