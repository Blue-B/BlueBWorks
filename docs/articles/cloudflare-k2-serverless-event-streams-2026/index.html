Cloudflare가 R2 위에 구축한 서버리스 이벤트 스트리밍 서비스 K2를 공개 베타로 내놨다. 이벤트를 순서가 있는 로그로 장기간 보관하고 여러 소비자가 독립적으로 읽을 수 있어 엣지 환경에서 대규모 데이터 파이프라인을 만들 때 Kafka 같은 별도 클러스터 운영 부담을 줄이는 선택지가 생겼다.

공식 출처

Cloudflare Blog — Announcing Cloudflare K2: serverless event streams blog.cloudflare.com

먼저 볼 것

  • R2 위에 구축된 순서 보장 durable log다.
  • 장기 보관과 fan-out 소비를 서버리스 형태로 제공한다.
  • 초기 버전 producer p99 지연은 약 1초라 저지연 큐와 용도가 다르다.

편집 메모

K2를 ‘서버리스 Kafka’라고만 부르면 중요한 차이가 빠진다. Cloudflare가 택한 핵심은 R2를 내구성 계층으로 쓰고 계산과 저장을 분리한 구조다. 그 결과 운영 부담과 장기 보관에는 이점이 있지만 초기 공개 버전의 producer p99 지연은 약 1초다. 초저지연 큐가 아니라 대규모 이벤트 이동·보관 문제에 맞춰 봐야 한다.

무엇이 나왔나

K2는 이벤트를 순서가 보장되는 durable log로 저장하고 여러 소비자가 각자 속도로 읽게 해주는 Cloudflare Developer Platform의 새 스트리밍 서비스다. R2 객체 스토리지를 기반으로 저장과 처리를 분리했고 장기 보관과 fan-out 소비를 지원한다.

개발자에게 왜 중요한가

트래픽 급증이나 소비자 장애가 생겨도 이벤트를 버리지 않고 버퍼링해야 하는 분석·로그·사기 탐지 같은 흐름을 서버리스 형태로 구성할 수 있다. 전통적인 Kafka 클러스터를 직접 배포하고 확장·복구하는 운영 부담 없이 Cloudflare 엣지와 가까운 스트리밍 파이프라인을 만들 수 있다는 점이 핵심이다.

직접 써볼 때 알아둘 점

현재 공개 베타이며 K2는 개별 메시지 재시도보다 대량 데이터 이동과 장기 보관에 초점을 맞춘다. 초기 버전은 R2에 세그먼트를 쓰는 구조 때문에 producer p99 지연이 약 1초라고 Cloudflare가 밝히고 있어 초저지연 메시지 큐가 필요한 경우에는 Queues 같은 다른 서비스와 비교해야 한다.
