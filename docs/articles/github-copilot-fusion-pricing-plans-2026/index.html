코파일럿 퓨전 출시와 Auto의 차이

코파일럿에서 모델을 고르다가 작업보다 선택에 시간을 쓰는 경우가 있습니다. 짧은 수정에는 가벼운 모델이면 될 것 같고, 여러 파일을 건드리는 버그에는 더 강한 모델이 필요해 보입니다. 복잡한 일을 마친 뒤에도 비싼 모델을 그대로 둔 채 사소한 수정을 계속하는 일도 생깁니다. GitHub가 10월 28일 Universe 2026에서 정식 공개한 Copilot Fusion은 이 선택을 작업마다 대신하는 기능입니다.

이름에 Fusion이 붙었지만 새 언어 모델 하나를 내놓은 것은 아닙니다. 기존 Auto의 모델 자동 선택과 Project HydraFusion의 여러 모델 조합을 묶어, 사용자는 모델 이름 대신 필요한 작업 강도를 고르게 했습니다. 요청을 받은 뒤 어떤 모델과 실행 방식을 쓸지는 Fusion이 결정합니다.

이번 글은 10월 30일 공개 발표와 공식 문서를 확인한 소식 해설입니다. 코파일럿 앱에 로그인해 실제 코딩 성능이나 결제 금액을 시험한 후기는 아닙니다. 아래 화면은 로그인 없이 읽을 수 있는 GitHub 공식 문서에서 직접 캡처했고, 공식 영상의 Fusion 설명은 1분 26초부터 나옵니다.

Standard, High, Max가 고르는 작업 강도

일상적인 코딩을 위한 Standard는 비용과 품질, 응답 시간을 함께 고려하며 작업마다 모델 하나를 고릅니다. High는 여러 파일에 걸친 수정이나 복잡한 버그처럼 범위가 비교적 분명한 큰 작업을 겨냥합니다. Max는 가장 깊은 추론이 필요한 문제에서 높은 성능을 우선하되 토큰 효율도 함께 고려하는 단계입니다. 강도를 높인다는 것은 같은 모델의 생각 시간만 늘린다는 뜻이 아닙니다.

High와 Max에서는 필요에 따라 여러 모델 호출이 들어갈 수 있습니다. 그래서 항상 Max를 켜면 가장 싸고 빠르게 끝난다고 받아들이면 곤란합니다. 공식 문서도 여러 모델의 검토가 들어가는 실행은 단일 모델보다 시간이 더 걸리고 AI 크레딧을 더 쓸 수 있다고 설명합니다. 쉬운 작업에 검토 호출을 불필요하게 붙이지 않는 것이 이 기능의 목적 중 하나입니다.

Fusion Fast라는 이름도 문서에 나오지만 사용자가 고르는 네 번째 강도는 아닙니다. VS Code 인라인 채팅에서 빠른 모델이 필요한 상황에만 쓰입니다. 모델 선택창에서 Standard, High, Max와 같은 방식으로 Fast를 찾을 필요는 없습니다.

무료 플랜은 Standard, High와 Max는 플랜 제한

모든 코파일럿 플랜에서 Fusion을 쓸 수 있다는 발표와 모든 강도를 쓸 수 있다는 말은 다릅니다. 10월 30일 공식 문서의 플랜별 표에서 Standard는 Free, Student, Pro, Pro+, Max, Business, Enterprise에 모두 포함돼 있습니다. High와 Max는 Pro+, Max, Business, Enterprise에만 포함되며 Free, Student, Pro에서는 제외됩니다. 기존 Pro 사용자라면 이 차이를 먼저 확인하는 편이 좋습니다.

아래 캡처의 체크 표시와 제외 표시가 그 구분입니다. 무료 계정도 Standard를 시험할 수 있지만 무료 플랜의 사용량 제한이 없어지는 것은 아닙니다. Fusion이라는 선택지가 생긴 것과 해당 플랜이 제공하는 크레딧이나 모델 범위는 별개입니다.

지원 클라이언트는 VS Code, GitHub Copilot 앱, Copilot CLI, JetBrains IDE입니다. 발표문은 클라이언트를 업데이트한 뒤 모델 선택창에서 Fusion과 강도를 고르라고 안내합니다. JetBrains의 별도 출시 안내에는 Auto를 대체하면서 점진 배포한다고 적혀 있어, 정식 출시 소식을 봤는데 메뉴가 없다는 이유만으로 곧바로 계정 오류라고 단정할 수는 없습니다.

퓨전 요금과 11월 30일까지 30% 할인

Fusion 자체에 별도로 붙는 요금은 없습니다. 실제로 사용한 각 모델의 표준 단가에 따라 비용을 합산합니다. GitHub의 모델 요금 문서는 입력, 출력, 캐시 토큰을 모델별로 계산한 뒤 AI 크레딧으로 환산하며 1크레딧을 0.01달러로 정의합니다. 따라서 Fusion 요청 한 번에 얼마라는 고정 가격표는 없습니다. 어떤 모델이 얼마나 많은 토큰을 썼는지가 중요합니다.

유료 코파일럿 플랜에는 2026년 11월 30일까지 Fusion 사용 시 모델 비용 30% 할인이 적용됩니다. 월 구독료를 30% 깎는 행사가 아니라는 점을 구분해야 합니다. 공식 Fusion 문서의 Billing 부분에서 대상과 기한을 함께 확인할 수 있습니다.

가령 할인 대상 모델 사용분이 원래 1달러라면 30% 할인 뒤 0.70달러가 되는 계산입니다. 이는 비율을 설명하기 위한 예시이지 실제 작업 가격을 측정한 결과가 아닙니다. High나 Max가 모델을 여러 번 호출해 할인 전 사용액 자체가 늘었다면, 할인율만 보고 Standard보다 지출이 적다고 말할 수 없습니다. 먼저 작은 작업에서 사용량을 보고 강도를 올리는 편이 비용을 파악하기 쉽습니다.

Single, Cascade, Critique의 실행 방식

Single은 모델 하나가 작업을 마치는 방식입니다. Cascade에서는 먼저 효율적인 모델이 초안을 만들고, 판단 단계가 그 결과를 받아들일지 더 강한 모델로 넘길지를 정합니다. 처음부터 모든 작업에 가장 비싼 모델을 배정하는 대신, 필요한 경우에만 강한 모델을 더 쓰려는 구조입니다. 간단한 수정이 첫 단계에서 끝날 수도 있습니다.

Critique는 초안을 다른 모델들이 검토한 뒤 피드백을 모아 원래 모델이 수정하는 방식입니다. 발표문은 초안과 검토, 수정의 큰 흐름을 설명하고, 상세 문서는 여러 모델이 병렬로 비평할 수 있다고 구체화합니다. 이 검토에는 추가 호출이 필요하므로 품질을 위해 시간과 크레딧을 더 쓰는 상황이 생깁니다.

실행 방식은 세션 전체에 한 번 고정되는 것이 아니라 요청마다 달라질 수 있습니다. 첫 질문은 Single로 답하고 후속 질문은 Critique로 처리할 수 있다는 뜻입니다. 사용자는 작업 중 각 단계와 사용 모델의 진행 상태를 볼 수 있고, 답변 아래 강도 이름에 마우스를 올려 사용된 모델 목록을 확인할 수 있다고 문서는 안내합니다. 중간 초안은 수정되거나 버려질 수 있어 최종 응답과 같다고 보면 안 됩니다.

60점과 비용 절반이라는 발표의 비교 조건

GitHub가 제시한 성능 수치는 Artificial Analysis Coding Agent Index에서 Fusion Max가 60점을 얻었다는 내용입니다. Claude Code의 Opus 5.5 Max와는 2점 이내 차이였고, 평균 작업당 API 비용과 토큰은 약 절반, 작업 시간은 약 40% 적었다고 발표했습니다. 공식 키노트 요약 영상에도 같은 비교가 나옵니다.

이 수치는 특정 평가에서 얻은 비교이지 모든 저장소의 비용을 절반으로 줄여준다는 약속이 아닙니다. 블로그가 독립적으로 다시 돌린 결과도 아닙니다. 구독료, 팀의 전체 청구액, 같은 질문을 직접 넣었을 때의 응답 속도와 곧바로 대응시키면 의미가 달라집니다. 모델 조합이 바뀌거나 요구하는 수정 범위가 다르면 결과도 달라집니다.

도입 판단에 쓰려면 팀에서 반복하는 작업을 정해 같은 통과 조건으로 비교해야 합니다. 예를 들어 테스트가 있는 버그 수정 몇 건을 골라 완료 여부, 검토에 든 시간, 실제 크레딧을 함께 기록하는 방식입니다. 이 비교 방법은 문서의 기능 설명을 바탕으로 제안하는 확인 기준이며, 여기서 실험을 했다는 뜻은 아닙니다.

회사 계정에서 메뉴가 안 보이는 경우

회사 계정에서는 내 구독만으로 사용 가능 모델을 결정하지 않습니다. Fusion은 조직과 엔터프라이즈가 허용한 모델 정책 안에서만 모델을 고릅니다. 관리자가 특정 모델을 Fusion에서만 제외하거나 Fusion의 기본 강도를 관리 설정으로 지정할 수 있습니다. 데이터 보관 지역이나 FedRAMP 조건, 평가용 모델 제한도 선택 가능한 모델에 영향을 줍니다.

Fusion이 쓸 수 있는 모델이 하나도 남지 않으면 모델 선택창에 Fusion 자체가 나타나지 않는다고 문서는 설명합니다. 이 경우 새 구독을 사는 것으로 해결된다고 가정하기보다 클라이언트 업데이트 상태와 조직 정책을 확인해야 합니다. 개인 계정에서는 보이는 메뉴가 회사 계정에 없는 이유를 좁힐 수 있습니다.

문서에는 일부 로컬 모델을 Standard가 선택하는 기능도 따로 소개돼 있습니다. 이 부분은 공개 프리뷰이고 로컬 모델 설치와 실험 기능 설정 조건이 붙습니다. Fusion 정식 출시와 로컬 자동 선택의 프리뷰 상태를 섞어, 아무 PC에서나 인터넷 없이 모든 강도를 쓸 수 있다고 해석해서는 안 됩니다.

초안을 버려도 파일 수정은 남을 수 있음

자동으로 검토 모델이 붙는다는 설명에서 놓치기 쉬운 제한이 있습니다. Fusion이 초안을 폐기해도 그 초안이 이미 작업 폴더에 만든 파일 수정은 자동으로 되돌아가지 않습니다. 공식 문서는 커밋 전에 변경 사항을 확인하라고 명시합니다. 최종 답변이 그럴듯한지 확인하는 것과 실제 diff를 읽는 것은 여전히 별개의 일입니다.

Fusion은 서브에이전트와 별개로 동작하며 서브에이전트를 시작하는 기능도 아닙니다. 여러 모델이 한 요청을 처리하는 것과 여러 에이전트가 서로 다른 저장소를 맡아 작업하는 것은 구분해야 합니다. 같은 Universe에서 발표한 Copilot Projects나 Automations의 역할까지 Fusion 하나의 기능으로 합치면 실제 사용 범위를 잘못 이해하게 됩니다.

기존 HydraFusion 사용자에게는 모델을 조합한다는 개념이 익숙할 수 있습니다. 이번 변화에서 볼 부분은 Auto와의 통합, 사용자가 고르는 강도, 플랜별 접근 범위와 실제 모델별 과금입니다. 공식 문서는 모델 풀과 실행 패턴이 바뀔 수 있다고도 적고 있습니다. 지금 표시된 선택지와 사용 내역을 기준으로 판단하고, 자동 선택을 켰더라도 파일 검토와 비용 확인은 남겨두는 편이 맞습니다.
