클로드 울트라는 기존 Max 20x의 새 이름이다

클로드의 월 200달러 요금제가 Ultra라는 이름으로 바뀌었습니다. 기존 Max 20x 구독자는 자동으로 Ultra로 옮겨지며 가격은 그대로입니다. 더 중요한 변화는 인증된 Ultra 계정의 5시간 사용량 제한이 사라진다는 점입니다. 다만 주간 한도는 남습니다. 무제한 요금제가 새로 생긴 것으로 받아들이면 실제 사용량과 기대가 어긋날 수 있습니다.

앤트로픽은 미국 시간 10월 30일, 한국 시간 10월 31일 새벽에 공식 Claude 계정으로 이름 변경을 발표했습니다. 기존 Max 5x는 Max, Max 20x는 Ultra가 됩니다. 발표에 적힌 월 가격은 각각 100달러와 200달러입니다. 기존 가입자가 새 이름을 적용받기 위해 해지한 뒤 다시 가입하거나 별도 전환 신청을 할 필요는 없습니다.

이번 이름 변경에서 숫자만 비교하는 것은 적절하지 않습니다. 예전 이름의 20x와 새 도움말에 적힌 주간 Pro 대비 10배는 같은 시간 구간을 나타내는 설명이 아닙니다. Ultra 도움말은 주간 사용량을 기준으로 Pro의 10배라고 명시합니다. 새 이름에서 배수가 빠졌다고 사용량이 절반으로 줄었다거나, 반대로 모든 제한이 없어진 것으로 단정할 근거는 아닙니다.

월 200달러는 웹 구독 기준입니다. 모바일 앱에서 구독하면 플랫폼에 따라 가격이 다를 수 있고, 실제 결제 통화나 적용 세금도 결제 화면의 조건을 따라야 합니다. 달러 표시 금액을 일정한 원화 구독료로 바꿔 소개하면 환율과 결제 경로의 차이를 놓치게 됩니다. 기존 구독자는 이름보다 다음 결제 금액과 현재 계정의 사용량 표시를 살펴보는 편이 실용적입니다.

5시간 제한 해제와 주간 한도는 따로 적용된다

일반적인 5시간 한도는 첫 메시지를 보낸 시점부터 시작하는 사용량 구간입니다. 그 안에서 정해진 사용량을 먼저 소진하면 구간이 끝나고 다시 채워질 때까지 기다려야 합니다. 하루 종일 매시간 조금씩 쓰는 사람보다 짧은 시간에 코딩 작업을 몰아서 실행하는 사람에게 더 크게 느껴질 수 있는 제한입니다.

인증된 Ultra 계정은 이 구간 제한 없이 주간 사용량 안에서 작업 시간을 배분할 수 있습니다. 예를 들어 오후 몇 시간 동안 코드 수정과 테스트 요청을 집중하는 작업이라면, 5시간 구간 때문에 먼저 멈추던 부담이 줄어드는 방향입니다. 그렇다고 작업마다 소비하는 사용량 자체가 사라지는 것은 아닙니다. 길고 복잡한 대화나 높은 노력 수준의 요청은 여전히 남은 주간 사용량에 영향을 줍니다.

Ultra에는 모든 모델에 적용되는 주간 한도와 Fable에 따로 적용되는 주간 한도가 있습니다. 도움말은 용량 관리와 공정한 접근을 위해 다른 제한이 적용될 수 있다고도 설명합니다. 따라서 5시간 제한 해제를 서비스의 끊김 없는 실행이나 특정 모델의 무제한 사용을 보장하는 약속으로 읽으면 안 됩니다.

주간 한도는 계정에 지정된 요일과 시각에 초기화됩니다. 그 주에 처음 사용한 시점이나 구독을 시작한 시점에 따라 매번 움직이는 방식이 아닙니다. 주말에 일을 몰아서 하는 사용자라면 본인의 초기화 시점을 기준으로 남은 작업을 배분할 수 있습니다. 같은 Ultra라도 계정별 초기화 시각이 다를 수 있으므로 다른 사람의 화면을 그대로 기준으로 삼을 필요는 없습니다.

Ultra 계정 인증은 자동이며 전화번호 확인과 다르다

5시간 제한이 없어지는 대상에는 인증된 계정이라는 조건이 붙습니다. 앤트로픽은 계정과 결제 이력 등의 요소를 이용해 Ultra 계정을 자동으로 인증한다고 설명합니다. 아직 인증되지 않은 계정에는 임시 제한이 적용되며, 인증이 끝나면 자동으로 해제됩니다. 사용자가 별도 신청을 해야 한다는 안내는 없습니다.

결제 과정의 전화번호 확인은 이 인증과 별개입니다. 전화번호를 확인했다고 해서 임시 사용량 제한이 곧바로 없어지는 것은 아닙니다. 이름이 Ultra로 바뀌었는데도 세션 제한이 남아 있다면, 구독 이름 변경과 인증 조건을 나눠 해석해야 합니다. 공개 도움말에는 모든 새 계정이 몇 시간 안에 인증된다는 식의 고정 처리 기간이 제시돼 있지 않습니다.

인증 여부를 구분하는 기준으로 도움말은 Settings의 Usage에서 Current session 막대가 보이는지를 제시합니다. 그 막대가 없으면 인증된 Ultra 계정이라는 설명입니다. 주간 사용량 막대가 남아 있는 것은 다른 문제입니다. 세션 표시가 사라져도 주간 사용량은 계속 관리되므로, 화면에서 막대 하나가 없어졌다는 이유로 모든 사용량 관리가 끝난 것은 아닙니다.

새로 가입할지 고민한다면 인증 완료 시점을 전제로 작업 일정을 잡지 않는 편이 낫습니다. 중요한 마감이 있는 날에 결제하면 즉시 세션 제한이 사라질 것이라고 기대하기보다는, 현재 계정에 적용되는 조건과 남은 사용량을 먼저 기준으로 삼아야 합니다. 기존 가입자는 자동 전환 대상이라는 점과 실제 제한 해제가 인증 조건에 따른다는 점을 함께 기억하면 됩니다.

Claude Code와 채팅은 같은 사용량을 나눠 쓴다

사용량 한도는 화면마다 독립된 지갑처럼 나뉘지 않습니다. Claude 웹, Claude Code, Claude Desktop에서 쓴 양이 같은 사용량 한도에 반영됩니다. 채팅 화면에서 자료를 길게 분석하고 터미널에서 코드 작업을 병행하면 두 작업이 같은 구독 사용량을 소비합니다. Ultra의 5시간 제한 해제도 이런 공유 구조 안에서 이해해야 합니다.

개발자에게 달라지는 것은 작업을 몰아서 할 때의 시간 제약입니다. 여러 제품을 쓴다고 각각 별도의 주간 예산이 생기는 것은 아닙니다. 코딩 에이전트에 큰 저장소를 읽히고 긴 테스트 결과를 반복 전달하는 작업과 짧은 질의응답은 소비량이 같지 않을 수 있습니다. 요청 횟수만 세어 남은 작업 가능 시간을 계산하기 어려운 이유입니다.

한 대화가 담을 수 있는 길이와 기간별 사용량도 다릅니다. 문맥 창은 한 대화에서 모델이 다룰 수 있는 정보의 범위이고, 사용량 한도는 일정 기간에 쓸 수 있는 총량입니다. 세션 제한이 없어진다고 하나의 대화에 어떤 크기의 문서든 끝없이 넣을 수 있는 것은 아닙니다. 긴 대화가 부담이 될 때 새 대화나 필요한 자료만 담은 프로젝트 구성을 고려하는 이유도 여기에 있습니다.

도움말은 노력 수준을 낮추거나 불필요한 도구를 끄고, 프로젝트 지침과 자료를 간결하게 유지하는 방법을 제안합니다. 이는 더 비싼 요금제에 가입하라는 이야기와 다릅니다. 간단한 수정까지 가장 높은 노력 수준으로 실행하기보다 작업에 맞게 범위를 정하면, 같은 주간 한도 안에서도 중요한 요청에 쓸 여지를 남길 수 있습니다.

월 API 크레딧은 구독 사용량과 별도 혜택이다

Ultra에는 월 200달러, Max에는 월 100달러의 Claude Platform API 크레딧도 안내돼 있습니다. 구독료와 같은 달러 숫자가 나온다고 현금 환급이나 구독료 차감을 뜻하는 것은 아닙니다. 자신의 앱과 에이전트에서 Claude API를 호출할 때 쓰는 별도 잔액입니다. 채팅이나 대화형 Claude Code의 주간 한도를 늘리는 용도로 바꿀 수 없습니다.

대상 구독은 활성 상태여야 하고 새 가입자는 해당 요금제에서 7일이 지난 뒤 크레딧을 받을 수 있습니다. 제공은 며칠에 걸쳐 순차 적용됩니다. 크레딧을 받으려면 Claude Console 조직과 연결하며, 한 구독은 한 조직에만 연결할 수 있습니다. 연결한 조직을 사용자가 직접 바꾸지 못한다는 조건도 있으므로 개인 개발 조직과 회사 조직을 섞어 선택하지 않는 것이 중요합니다.

API 크레딧은 결제 주기마다 새로 제공되고 남은 금액은 다음 주기로 이월되지 않습니다. 연결된 조직에서 API 키를 가진 구성원이 같은 잔액을 사용하며, 월 크레딧이 먼저 소비됩니다. 크레딧이 끝났을 때 구매한 잔액이나 자동 충전이 있으면 그쪽 사용이 이어질 수 있습니다. 따라서 무료로 받은 잔액만 쓸 생각이라면 조직에 이미 설정된 결제 조건까지 구분해야 합니다.

대화형 Claude Code와 Claude 또는 Cowork의 추가 사용량, Bedrock이나 Vertex AI 같은 외부 플랫폼 사용은 이 크레딧의 대상이 아닙니다. 직접 API 키로 실행하는 Agent SDK와 일부 비대화형 실행은 청구 경로에 따라 대상이 될 수 있지만, 구독 계정으로 로그인한 작업이 자동으로 API 크레딧을 쓰는 것은 아닙니다. 혜택 금액보다 어떤 인증과 청구 경로를 쓰는지가 먼저입니다.

Max와 Ultra 선택은 한 주 작업량을 기준으로 본다

기존 월 200달러 구독자라면 자동 전환과 인증 상태를 살피면 됩니다. 월 100달러 Max 사용자는 이름 변경만으로 Ultra의 5시간 제한 해제가 적용되지는 않습니다. 두 요금제의 가격이 그대로인 상황에서 판단할 것은 새 이름의 인상보다 자신의 작업이 세션 제한에 먼저 막혔는지, 주간 한도에 먼저 막혔는지입니다.

짧은 시간에 큰 작업을 몰아서 처리하다가 자주 중단됐다면 인증된 Ultra의 변화가 직접적인 의미를 가질 수 있습니다. 반대로 일주일 전체 사용량을 이미 빠르게 소진하는 사람에게는 5시간 제한이 없어져도 남은 주간 예산이 중요합니다. 시간 제약과 총량 제약을 구분해야 업그레이드 뒤에도 같은 문제를 겪는 일을 줄일 수 있습니다.

API 개발을 한다면 월 크레딧도 고려할 수 있지만, 쓰지 않고 만료될 크레딧을 그대로 구독료 절약분으로 계산하는 것은 맞지 않습니다. 현재 앱의 실제 API 사용량, 조직 연결 조건, 만료 주기와 대화형 도구의 제외 범위를 함께 보면 됩니다. 웹 구독료 200달러와 API 크레딧 200달러는 이름이 같은 달러 금액일 뿐, 서로 자동으로 상계되는 비용 항목은 아닙니다.

이번 변화에서 달라진 것은 요금제 이름과 인증된 Ultra 계정의 세션 운용 방식입니다. 주간 한도, 모델별 제한, API 청구는 여전히 따로 읽어야 합니다. 구독을 바꾸기 전에는 자신의 현재 사용 패턴과 남은 주간 사용량을 기준으로 판단하고, 기존 구독자는 새 이름을 적용받으려고 불필요하게 해지하거나 다시 결제할 필요가 없습니다.
