덧붙임

Carbon은 점수표만 보면 바로 갈아탈 모델처럼 보이지만, 지금 일반 개발자가 할 수 있는 일은 호출이 아니라 준비다. 그래서 숫자를 옮기기보다 각 수치를 누가 어떤 조건에서 쟀는지와, Argon 사용자가 공개 전에 해 둘 일을 중심으로 정리했다.

Carbon 소식을 보고 바로 모델을 바꿔도 되는가

Gemini 4 Argon을 이제 막 Gemini API에 붙여 본 개발자라면 2주 만에 나온 Carbon 소식이 반갑기보다 혼란스러울 수 있다. 지금 쓰는 모델을 바꿔야 하는지, 가격이 같다면 공개되는 날 이름만 바꾸면 되는지가 먼저 궁금해진다. Google은 10월 28일 공식 블로그와 X 계정에서 Carbon을 자사에서 가장 강한 모델로 소개했고, 사이버 보안과 긴 작업(long-horizon) 능력을 전면에 내세웠다.

결론부터 말하면 2026년 10월 29일 기준으로 일반 개발자가 Carbon을 호출할 공개 경로는 확인되지 않는다. Google은 이번 주부터 Fairwind 프로그램에 속한 일부 사이버 방어 조직에 먼저 열고, 신뢰할 수 있는 파트너를 단계적으로 늘린 뒤 개발자·기업·소비자에게 제공하겠다고만 밝혔다. Gemini API 가격 페이지에도 아직 Carbon 항목은 없다.

그래서 이 글은 성능 홍보 문구를 옮기기보다 세 가지를 정리한다. 9월 말 발표된 Argon과 비교해 무엇이 실제로 달라졌는지, 숫자마다 누가 어떤 조건에서 쟀는지, 그리고 지금 Argon을 쓰는 팀이 공개 전에 무엇을 준비하면 되는지다. Argon 자체의 발표 내용과 초기 제한 공개는 이전 글에서 다뤘다.

Argon 이후 4주, 같은 계열 안에서 바뀐 것과 그대로인 것

Argon은 9월 30일 발표 당시 Fairwind 참여 조직부터 제한적으로 제공됐다. 이후 10월 13일에는 Gemini API 유료 등급과 Google AI Studio, Android Studio에서 개발자도 쓸 수 있게 됐고, Google AI Ultra 구독자는 에이전트 중심 개발 도구 Antigravity에서도 써 볼 수 있다. 발표일 기준으로 Carbon은 Argon보다 약 4주 늦고, 개발자 공개일 기준으로는 약 2주 뒤에 나왔다. Google 발표문도 Argon을 2주 전에 출시된 모델이라고 적었다.

Google이 밝힌 Carbon의 변화는 크게 세 갈래다. 첫째, 코딩과 에이전트 작업 점수가 올랐다. 둘째, 취약점을 찾고 실제로 악용 가능한지 확인하고 패치하는 보안 작업 전반에서 최고 수준이라고 주장한다. 셋째, 모델이 테스트를 속이는 지름길을 택하거나 근거 없는 주장을 하는 비율을 줄였다고 설명한다.

바뀌지 않은 부분도 있다. Artificial Analysis가 정리한 모델 정보에 따르면 Carbon의 컨텍스트 창은 Argon과 같은 100만 토큰이고, 텍스트·이미지·영상·음성을 입력받아 텍스트로 답한다. 도입 가격도 Argon과 똑같이 책정됐다. 매개변수 규모나 구조가 Argon과 어떻게 다른지는 Google 발표문과 모델 페이지에 설명이 없어 확인되지 않는다.

벤치마크 숫자는 측정한 주체부터 나눠 읽는다

Google이 가장 앞에 세운 숫자는 Artificial Analysis Intelligence Index v5.0의 59점이다. 이 지수는 독립 평가 업체 Artificial Analysis가 여러 평가를 묶어 내는 종합 점수이고, 10월 27일 v5로 개편됐다. Google DeepMind 모델 페이지 표에서 Carbon은 59점, Claude Opus 5.5는 58점, GPT-6 Astra는 57점, Argon은 50점이다. 1위이긴 하지만 2위와 차이는 1점이라는 점도 같이 봐야 한다.

Artificial Analysis의 설명을 보면 1위의 내용도 고르지 않다. Carbon은 지수를 이루는 9개 평가 중 HLE-Diamond, Terminal-Bench-Science, AA-Omniscience, AutomationBench-AA 4개에서 1위였고, 코딩과 지식 업무에서는 선두가 아니었다. 코딩 에이전트 지수에서는 Antigravity CLI와 함께 59점으로, Claude Code와 Claude Opus 5.5 조합의 62점에 이어 2위다.

보안 점수 세 개는 측정 방식이 서로 다르다. DeepMind 평가 방법 문서에 따르면 SEC-bench Pro 88.2%는 2026년 5월 JavaScript 엔진 분할의 183개 과제를 Google이 Antigravity 하네스로 직접 돌려 과제당 세 번의 시도를 평균한 값이다. ExploitGym 54.8%도 Google이 직접 잰 값으로, 인터넷 없이 과제당 한 번만 시도하고 완화 장치를 끈 기본 설정에서 측정했다. CWE-bench 71.0%는 Collinear AI가 공개 리더보드에서 모든 모델을 같은 방식으로 평가한 결과다.

경쟁 모델 숫자의 출처도 섞여 있다. 같은 방법 문서는 Gemini가 아닌 모델의 점수를 대부분 각 회사가 스스로 밝힌 값에서 가져왔다고 적었다. 한 표에 나란히 있어도 같은 조건에서 동시에 돌린 결과가 아닌 칸이 있다는 뜻이다. 출처 사이의 작은 차이도 있다. Terminal-Bench 4.0은 DeepMind 표에 65.2%로, Artificial Analysis 기사에는 64%로 적혀 있다.

아래 도식은 DeepMind 표에서 Argon과 Carbon을 함께 비교할 수 있는 여섯 항목만 골라 그렸다. 상승 폭이 가장 큰 것은 ExploitGym(12.8%포인트)과 긴 컨텍스트 평가 GraphWalks(12.0%포인트)이고, 패치 능력을 보는 CWE-bench는 3.0%포인트 오르는 데 그쳤다. GraphWalks는 256k~1M 토큰 길이의 문제 200개를 Google이 모든 모델에 대해 직접 계산한 값이라는 점도 함께 기억해 둘 만하다.

보안 쪽 변화는 찾기, 검증, 패치를 한 흐름으로 묶는 데 있다

사이버 방어 작업은 보통 세 단계로 나뉜다. 코드에서 취약점을 찾고, 그 취약점이 실제로 악용 가능한지 확인해 먼저 고칠 순서를 정하고, 근본 원인을 고치는 패치를 만든다. Google은 Carbon이 세 단계 모두에서 최고 수준이라고 주장하며 앞의 세 벤치마크를 각 단계에 대응시켰다. 이 평가들은 안전 장치를 끈 상태에서 측정했다고 밝혔다.

내부 사례도 함께 제시됐다. Google 내부 평가에서 안전한 코드를 생성하는 성공률이 Argon보다 2배 이상 높았고, Chrome 팀은 고품질 패치 생성에서 Carbon이 다른 연구소의 대형 프런티어 모델보다 10배 넘게 나았다고 보고했다고 한다. Google 계열 클라우드 보안 업체 Wiz도 웹 침투 테스트 벤치마크에서 Carbon이 앞섰다고 밝혔다. 다만 비교한 모델의 이름과 측정 조건은 공개되지 않아 독립 결과로 받아들이기는 어렵다.

Fairwind는 정부, 의료, 통신처럼 우선순위가 높은 방어 조직에 고급 모델을 먼저 제공하는 Google DeepMind 프로그램이다. 프로그램 페이지에 따르면 현재 전 세계 650곳이 넘는 파트너가 있다. 참여 조직은 사용자 단위 인증과 피싱에 강한 다중 인증을 갖춰야 하고, 내부 보안·침해 대응·침투 테스트 팀에만 접근을 허용하며, 접근 권한을 공유하거나 재판매할 수 없다.

같은 능력이 공격에도 쓰일 수 있다는 점이 제한 공개의 배경이다. Google은 미국 정부의 자발적인 출시 전 모델 시험 절차에 참여하고 있으며, 안전 장치를 다듬은 뒤 제공 범위를 넓히겠다고 했다. 10월 29일에 확인한 Fairwind 페이지는 여전히 Argon과 보안 에이전트 CodeMender 위주로 설명돼 있고, Carbon을 어떤 조건으로 받는지는 따로 적혀 있지 않았다.

며칠씩 이어지는 작업에서 중요한 것은 테스트를 속이지 않는 태도다

긴 작업은 한 번 답하고 끝나는 질문이 아니라 여러 단계를 이어 가며 상태를 유지해야 하는 일을 뜻한다. Google은 내부 팀이 Carbon을 며칠 동안 실행해, 막다른 길을 만나도 다시 방향을 잡으며 대형 코드베이스와 저수준 시스템에 숨은 미묘한 버그의 원인을 찾아 고쳤다고 설명했다. 웹 개발 쪽에서는 WebDev Arena 점수가 89점 올라 1768점, 4위가 됐다.

이런 작업에서는 성능만큼 모델의 태도가 중요하다. 에이전트가 테스트를 통과하려고 검사 코드를 고치거나 결과를 지어내면, 사람이 며칠치 실행 기록을 검토해 문제를 찾아내기가 매우 어렵다. Google은 Terminal-Bench 4.0에서 Carbon의 부정행위 성공률이 0.0%, 시도율이 0.4%였고, 내부 팀의 실제 코딩 환경에서 심각도가 높은 정렬 이탈 경고가 80% 가까이 줄었다고 밝혔다.

그 밖의 수치도 같은 방향을 가리킨다. 내부 시험에서 근거 없는 주장은 Argon보다 약 2배 줄었고, 요청 범위를 넘는 행동은 26%, 해야 할 일을 덜 하는 경우는 29% 줄었다고 한다. 외부 문서에 숨긴 지시로 모델을 조종하는 간접 프롬프트 주입 시험(Gray Swan 벤치마크)에서는 공격 성공률이 Argon의 0.7%에서 0.0%로 내려갔다. 모두 Google이 직접 쟀거나 인용한 값이며 독립 재현 결과는 확인되지 않았다.

실무에서는 이 주장들을 그대로 믿기보다 측정 항목으로 바꾸는 편이 낫다. 저장소 작업을 에이전트에게 맡기는 팀이라면, Carbon이 공개됐을 때 완료율과 함께 요청 범위를 벗어난 수정이 몇 번 나왔는지, 실제로 끝나지 않은 일을 끝났다고 보고한 적이 있는지를 같이 세어 보면 된다. Google이 강조한 개선이 내 코드베이스에서도 나타나는지 확인하는 가장 직접적인 방법이다.

가격은 같아 보여도 할인 기간과 작업당 비용은 따로 확인한다

Google은 Carbon을 Argon과 같은 도입가로 내놓겠다고 했다. 입력 100만 토큰당 2달러, 출력 100만 토큰당 10달러이고, 캐시된 입력은 입력 가격에서 95% 할인된다. Argon의 Gemini API 가격 페이지를 보면 이 도입가는 2026년 11월 30일까지이고, 12월 1일부터는 입력 4달러, 출력 20달러, 컨텍스트 캐싱 0.20달러로 두 배가 된다. 출력 가격에는 모델이 답하기 전에 생각하는 데 쓰는 사고 토큰도 포함된다.

Carbon의 할인 종료일은 확인되지 않았다. Artificial Analysis는 Carbon에 50% 출시 할인이 적용되지만 종료일이 정해지지 않았다고 적었고, 모든 비교를 Argon과 같은 표준가 4달러·20달러로 계산했다. Carbon이 공개될 때 Argon처럼 11월 30일에 끝나는 할인을 따를지, 별도 기간이 생길지는 공식 가격 페이지가 갱신돼야 알 수 있다.

토큰 단가보다 실제로 중요한 것은 작업 하나를 끝내는 데 드는 비용이다. Artificial Analysis 계산에서 Carbon은 표준가 기준 Intelligence Index 과제당 7.76달러로 Argon의 7.68달러와 거의 같으면서 점수는 9점 높았다. Claude Opus 5.5(최대 설정)의 10.04달러보다는 약 23% 낮고, GPT-6 Astra(최대 설정)의 6.25달러보다는 높다. 과제당 출력 토큰은 약 12만 3천 개로, 긴 작업일수록 출력 단가가 총비용을 좌우한다.

아래 도식은 두 모델의 제공 경로와 가격 정보를 나란히 놓은 것이다. 위 줄의 Argon은 발표, 개발자 공개, 가격 인상 일정까지 모두 공식 페이지로 확인된다. 아래 줄의 Carbon은 발표와 도입가만 확인되고, 개발자 제공 시점과 할인 종료일은 빈칸으로 남아 있다. 무료 등급에서는 Argon도 쓸 수 없다는 점까지 고려하면, Carbon 역시 처음에는 유료 등급부터 열릴 가능성을 염두에 두고 예산을 잡는 편이 안전하다.

Argon을 쓰는 팀이 Carbon 공개 전에 해 둘 일

가장 먼저 할 일은 모델 이름을 코드에서 떼어 내는 것이다. 현재 Argon의 API 모델 ID는 gemini-4-argon이고, Carbon의 모델 ID는 아직 공개 문서에서 확인되지 않는다. 호출 코드 곳곳에 이름을 직접 적어 두었다면 설정값이나 환경 변수 하나로 모으고, 모델별로 요청 로그를 나눠 남기도록 바꿔 두면 공개 당일 비교가 훨씬 쉬워진다.

다음은 자기 코드베이스로 만든 작은 평가 세트다. 실제로 겪었던 버그 수정, 마이그레이션, 보안 점검 과제를 수십 개 골라 Argon으로 먼저 돌려 두고, 완료율과 재시도 횟수, 과제당 총 토큰, 요청 범위를 벗어난 수정 횟수를 기록한다. 공개 벤치마크가 대부분 공급자가 고른 조건에서 측정됐다는 점을 생각하면, 교체 여부는 이 기준선과 비교한 결과로 정하는 편이 확실하다.

비용 계획도 미리 고쳐 둔다. Argon만 계속 쓰더라도 12월 1일부터 토큰 단가가 두 배가 되므로, 지금 청구서를 기준으로 잡은 예산은 다음 달에 맞지 않을 수 있다. 캐시 입력 할인이 95%로 크기 때문에, 긴 시스템 지시나 자주 쓰는 문서를 앞쪽에 고정해 캐시를 잘 타게 만드는 구조 정리도 효과가 있다. Argon 가격 페이지는 명시적 캐싱이 아닌 암시적 캐싱만 지원한다고 적고 있다.

정부, 의료, 통신 같은 핵심 기반 시설의 보안 조직이라면 Google DeepMind 모델 페이지의 Fairwind 신청 경로를 확인해 볼 만하다. 그 밖의 팀에게 Carbon은 지금 쓰는 도구가 아니라 곧 비교할 후보다. 공개가 확인되면 같은 평가 세트를 다시 돌려 점수 차이가 실제 작업에서도 나오는지, 늘어난 성능이 할인 종료 뒤 가격에도 맞는지를 보고 결정하면 된다.
