오픈소스 Open source

Cloudflare가 Clef와 Clef-flash라는 결정 모델을 공개하고 Workers AI에서 바로 쓸 수 있게 했다. 자유문장을 생성하는 대신 정해진 선택지의 확률을 반환해 라우팅·도구 선택·분류처럼 에이전트 내부의 반복 결정을 더 짧고 예측 가능한 흐름으로 처리하는 데 초점을 맞춘다.

공식 출처

Cloudflare Blog — Introducing Clef: our open-source decision models, and new RL fine-tuning platform blog.cloudflare.com

먼저 볼 것

  • 자유문장 대신 선택지별 확률을 반환하는 decision model이다.
  • Weights가 Apache 2.0으로 공개됐다.
  • 라우팅·분류·가드레일 같은 좁은 판단 단계에 초점을 맞춘다.

편집 메모

에이전트 시스템에서 의외로 비싼 부분은 ‘답변 생성’이 아니라 수없이 반복되는 작은 결정이다. Clef는 도구 선택·라우팅·분류처럼 선택지가 정해진 판단을 생성형 LLM에서 떼어내려는 시도다. 모델 크기보다 실제 업무 데이터에서 오분류 비용이 얼마나 줄어드는지 보는 게 중요하다.

무엇이 나왔나

Cloudflare는 Clef와 Clef-flash를 Workers AI에 공개하고 모델 가중치를 Apache 2.0 라이선스로 Hugging Face에 공개했다. 두 모델은 자유형 텍스트를 생성하지 않고 스키마로 지정한 선택지마다 확률을 반환하며 Jev 계열 API와 호환되도록 설계됐다.

개발자에게 왜 중요한가

에이전트의 모든 판단에 큰 언어모델을 호출하는 대신 도구 선택, 요청 분류, 가드레일, 라우팅처럼 답의 범위가 정해진 단계만 별도 결정 모델에 맡기는 구조를 실제 서비스에 적용하기 쉬워졌다. 출력 형식을 코드가 바로 소비하기 쉬운 형태로 고정할 수 있다는 점도 실용적이다.

직접 써볼 때 알아둘 점

Clef는 큰 모델이고 Clef-flash는 더 작은 지연 중심 모델이라 용도와 실행 환경에 맞춰 골라야 한다. Cloudflare가 공개한 벤치마크는 자사 평가 결과이므로 그대로 일반화하기보다 자신의 라우팅·분류 작업에서 정확도와 지연을 직접 비교하는 편이 안전하다.
