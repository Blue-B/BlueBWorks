tar 압축 풀기 명령어, tar.gz 압축과 경로 지정

tar.gz는 tar -xzf 한 줄로 풀고, 풀 위치는 -C로 정합니다. 경로 지정과 압축하기, 윈도우에서 푸는 법까지 실제 출력으로 정리했습니다.

요약
  • 압축 풀기는 tar -xzf 파일.tar.gz, 압축은 tar -czf 파일.tar.gz 폴더 입니다. f 바로 뒤에는 파일 이름이 와야 해서 f를 묶음 맨 끝에 둡니다.
  • 풀 위치는 -C 폴더로 정합니다. 폴더가 없으면 Cannot open 오류로 멈추니 먼저 만들어 둡니다.
  • 압축 안의 맨 위 폴더를 빼고 풀려면 --strip-components=1을 붙입니다. 풀기 전에 -t로 목록을 보면 어디에 풀릴지 알 수 있습니다.
  • 풀 때는 z나 J를 빼고 tar -xf만 써도 형식을 알아서 찾습니다. 이름과 실제 형식이 다른 파일은 오히려 이쪽이 풀립니다.
  • 윈도우 10 빌드 17063 이후에는 tar.exe가 들어 있어 PowerShell에서 같은 명령으로 풀 수 있고 zip도 다룹니다.

tar 압축 풀기, tar -xzf 한 줄

깃허브 릴리스나 서버 백업에서 받은 파일이 .tar.gz로 끝나면 tar 명령 한 줄로 풀 수 있습니다. 리눅스와 맥, WSL에는 기본으로 들어 있고 윈도우 10 이후 버전에도 tar.exe가 있습니다.

Ubuntu 24.04(WSL)의 GNU tar 1.35로 연습용 myapp 폴더를 묶었다가 다시 풀어 봤습니다. 소스 파일 몇 개와 1.3MB쯤 되는 로그 파일이 든 폴더였는데, tar.gz로 묶으니 65,102바이트가 됐습니다.

풀 때는 x(풀기), z(gzip), f(파일 이름)를 붙인 tar -xzf 뒤에 파일 이름을 씁니다. 아무 메시지 없이 프롬프트로 돌아오면 성공입니다.

아래에서는 out1이라는 빈 폴더에 풀었고, 그 안에 myapp 폴더가 원래 모양 그대로 생겼습니다. -C 없이 치면 지금 있는 폴더에 풀립니다.1

tar 옵션 글자 뜻, x c t z J j f v

tar 옵션은 글자마다 뜻이 정해져 있습니다. x는 풀기, c는 새로 묶기, t는 목록 보기이고 이 셋 중 하나는 꼭 들어갑니다.

z는 gzip, 대문자 J는 xz, 소문자 j는 bzip2 압축입니다. v는 처리하는 파일 이름을 한 줄씩 보여 주고, f는 바로 다음 단어를 압축 파일 이름으로 받습니다.

그래서 f는 묶음 맨 끝에 둡니다. 순서를 바꿔 tar -xfz로 치면 f 뒤에 붙은 z를 파일 이름으로 읽어 버립니다. 실제로 z라는 파일을 열 수 없다는 Cannot open 오류가 나고 아무것도 풀리지 않았습니다.

외우기 어렵다면 풀기는 xzf, 묶기는 czf, 목록은 tzf 세 묶음만 기억해도 대부분 해결됩니다.1

풀기 전에 압축 파일 목록 보기, tar -tzf

받은 압축 파일이 어떤 구조인지 모를 때는 풀기 전에 t로 목록부터 봅니다. 맨 위에 myapp/ 같은 폴더 하나가 있으면 그 폴더째 풀리고, 파일 이름이 바로 나열돼 있으면 지금 폴더에 흩어져 풀립니다.

압축 파일 하나를 홈 폴더에서 그냥 풀었다가 파일 수십 개가 섞여 버리는 일은 대부분 이 차이를 몰라서 생깁니다. 목록이 길면 grep으로 필요한 파일만 걸러 봐도 됩니다.

v를 더해 tar -tvzf로 보면 권한과 크기, 날짜까지 나옵니다. 풀기 전에 로그처럼 큰 파일이 들어 있는지 볼 때 편합니다.1

tar 압축 풀기 경로 지정, -C 폴더

지금 폴더가 아닌 곳에 풀고 싶으면 -C 뒤에 폴더를 적습니다. GNU tar 설명서는 -C를 작업 폴더를 바꾸는 옵션으로 설명하는데, 풀 때는 그 폴더 안에 풀린다고 보면 됩니다.

-C로 적은 폴더는 미리 있어야 합니다. 없는 폴더 이름을 주니 Cannot open 오류와 함께 아무것도 풀지 않고 멈췄습니다. mkdir로 폴더를 먼저 만들고 같은 명령을 다시 치면 됩니다.

-C는 -f로 준 압축 파일 경로에는 영향을 주지 않습니다. 압축 파일은 지금 폴더 기준 경로 그대로 적으면 됩니다.

풀 폴더를 따로 정해 두면 압축 안에 맨 위 폴더가 없더라도 파일이 다른 파일과 섞이지 않습니다. 처음 받는 압축 파일은 빈 폴더를 하나 만들어 그 안에 푸는 습관을 들이면 정리가 쉽습니다.2

맨 위 폴더 없이 풀기, --strip-components

압축 안에 myapp/ 같은 맨 위 폴더가 있는데 그 폴더 없이 내용만 풀고 싶을 때가 있습니다. 이미 만들어 둔 프로젝트 폴더에 새 버전을 덮어 풀 때가 그렇습니다.

--strip-components=1을 붙이면 경로 앞부분 한 단계를 떼고 풉니다. 2를 주면 두 단계를 뗍니다.

몇 단계를 뗄지 헷갈리면 먼저 목록 보기에 같은 옵션과 --show-transformed-names를 붙여 봅니다. GNU tar 설명서도 풀기 전에 이렇게 결과를 미리 보라고 권합니다. 아래처럼 myapp/가 빠진 이름이 보이면 그대로 풀면 됩니다.3

파일 하나나 폴더 하나만 골라 풀기

전체를 풀 필요 없이 몇 개만 꺼내려면 압축 파일 이름 뒤에 목록에 나온 경로를 그대로 적습니다. 폴더 경로를 주면 그 아래 파일이 함께 풀립니다.

경로는 대소문자까지 똑같아야 합니다. README.md를 README.MD로 적으니 Not found in archive가 나오고 실패로 끝났습니다. 이름이 헷갈리면 -t 목록에서 복사해 붙이는 편이 빠릅니다.

*.js처럼 패턴으로 고를 때 GNU tar는 --wildcards를 붙이고 패턴을 작은따옴표로 감쌉니다. 따옴표가 없으면 셸이 먼저 지금 폴더의 파일 이름으로 바꿔 버릴 수 있습니다.1

tar.gz 압축하기, 폴더 통째로와 일부 빼기

압축할 때는 x 대신 c를 씁니다. tar -czf 뒤에 만들 파일 이름을 먼저 쓰고, 묶을 폴더나 파일을 그 뒤에 둡니다.

로그나 node_modules처럼 빼고 싶은 폴더가 있으면 --exclude를 붙입니다. 로그 폴더를 빼고 같은 폴더를 묶으니 65,102바이트이던 파일이 275바이트로 줄었습니다.

절대 경로로 묶으면 Removing leading 이라는 메시지가 한 줄 나옵니다. 오류가 아니라 맨 앞의 /를 떼고 저장했다는 뜻입니다. 목록을 보면 tmp/로 시작하는 상대 경로로 들어가 있습니다.

절대 경로 그대로 풀리면 시스템 파일을 덮어쓸 수 있어서, GNU tar가 기본으로 막아 두는 동작입니다. 압축 파일을 받는 사람 쪽에서는 이렇게 상대 경로로 들어 있는 편이 다루기 쉽습니다.3

tar.gz, tar.xz, tar.bz2 차이

z, J, j는 압축 방식만 다릅니다. GNU tar 설명서의 표를 보면 z는 gzip, j는 bzip2, J는 xz이고 이 밖에 zstd 같은 형식도 옵션으로 고를 수 있습니다.

파일 이름이 .tgz로 끝나는 경우도 있는데, 확장자를 짧게 줄인 것이고 안은 tar.gz와 같은 gzip 형식입니다. 풀 때는 똑같이 tar -xzf나 tar -xf를 쓰면 됩니다.

어느 형식으로 묶을지는 받는 쪽을 먼저 생각하면 편합니다. gzip은 이번에 돌려 본 Ubuntu와 윈도우 tar 양쪽에서 따로 설치 없이 바로 됐고 묶는 속도도 빨랐습니다. 크기를 더 줄여야 할 때 xz를 고르면 됩니다.1,5

tar.xz가 가장 작았고 bz2는 bzip2: not found

같은 폴더를 세 가지로 묶어 크기를 비교했습니다. 압축하지 않은 tar가 1,372,160바이트, tar.gz가 65,102바이트, tar.xz가 14,068바이트였습니다.

같은 형식의 줄이 반복되는 로그라 차이가 크게 났습니다. 대신 xz는 0.589초가 걸려 gzip의 0.075초보다 여덟 배 가까이 느렸습니다. 사진이나 이미 압축된 파일이 많은 폴더라면 차이가 훨씬 작습니다.

bz2에서는 한 번 막혔습니다. Ubuntu 24.04 WSL에는 bzip2 프로그램이 기본으로 깔려 있지 않아 tar -cjf가 bzip2: not found로 실패했고, 0바이트짜리 myapp.tar.bz2 파일만 남았습니다.

sudo apt install bzip2로 패키지를 깔고, 실패하면서 생긴 빈 파일은 지운 뒤 다시 묶으면 됩니다. 남은 0바이트 파일을 모르고 옮기면 받는 쪽에서 풀리지 않습니다.1

tar -xf로 형식 상관없이 풀기, not in gzip format 해결

풀 때는 z나 J를 빼도 됩니다. GNU tar 설명서는 압축 파일을 읽을 때 형식을 알아서 알아본다고 적고 있고, 실제로 tar -xf만으로 tar.xz 파일이 그대로 풀렸습니다.

형식 글자를 잘못 붙이면 오히려 실패합니다. 실제로는 xz 형식인 파일을 .tar.gz 이름으로 바꿔 두고 -xzf로 풀자 not in gzip format 오류가 나왔습니다.

받은 파일 이름과 실제 형식이 다를 때 자주 보는 오류입니다. file 명령으로 진짜 형식을 보면 XZ라고 나오고, z를 빼고 tar -xf로 풀면 문제없이 풀립니다.

다만 cat이나 curl 출력처럼 파이프로 넘길 때는 형식을 알아서 못 찾습니다. 이때는 Archive is compressed. Use -z option처럼 붙일 옵션을 tar가 직접 알려 주니, 말한 글자를 붙이면 됩니다.1

윈도우에서 tar 압축 풀기, tar.exe와 bsdtar

윈도우 10 인사이더 빌드 17063부터 tar와 curl이 윈도우에 기본으로 들어갔습니다. 따로 설치하지 않아도 명령 프롬프트나 PowerShell에서 tar를 바로 칠 수 있습니다.

윈도우 11 Pro에서 tar --version을 쳐 보면 GNU tar가 아니라 bsdtar 3.8.8(libarchive)이 나옵니다. 그래도 리눅스에서 만든 tar.gz를 -xf, -C, -t, --strip-components로 풀어 보니 결과는 같았습니다.

차이는 두 곳에서 보였습니다. -C 폴더가 없을 때 오류 문장이 could not chdir to로 나오고, 옵션을 파일 이름 뒤에 붙이면 옵션으로 읽지 않습니다.

리눅스 GNU tar에서는 끝에 붙인 -v가 그대로 먹혔지만, 윈도우 tar는 -v를 풀 파일 이름으로 읽고 Not found in archive를 냈습니다. 윈도우에서는 옵션을 모두 파일 이름 앞에 두는 습관이 안전합니다.

bsdtar는 zip도 다룹니다. tar -a -cf로 만들 파일 이름을 .zip으로 주면 zip 형식으로 만들고, 받은 zip도 tar -xf로 풀립니다. 탐색기 메뉴 대신 명령 한 줄로 처리하고 싶을 때 쓸 만합니다.4,5
