jQuery 4.1.0과 3.8.0, 버전 확인과 업그레이드 방법

jQuery 4.1.0과 3.8.0이 함께 나왔습니다. 3.x는 이제 중요한 수정만 받으니, 버전 확인부터 4.x로 옮기는 순서까지 다룹니다.

3줄 요약
  • jQuery 3.8.0은 3.x의 마지막 기능 릴리스입니다. 이후 3.x는 중요한 보안 수정과 버그 수정만 받습니다.
  • 두 버전 모두 선택자 정규식이 특정 문자열에서 페이지를 멈추게 하던 문제(ReDoS)를 고쳤습니다. 3.x에 남더라도 3.8.0으로는 올리는 편이 좋습니다.
  • 4.x로 옮길 때는 jQuery 4.1.0 위에 압축하지 않은 jQuery Migrate 4.x를 붙이고, 콘솔 경고를 하나씩 고친 뒤 Migrate를 뺍니다.

jQuery 4.1.0과 3.8.0, 같은 날 나온 두 버전

오래된 관리자 화면이나 회사 홈페이지를 열어 보면 아직 jQuery가 붙어 있는 경우가 많습니다. 그런 코드를 맡고 있다면 이번 주 소식은 한 번 챙겨 볼 만합니다.

jQuery 팀은 미국 시간 11월 17일 4.1.0과 3.8.0을 함께 내놓았습니다. 4.1.0은 올해 1월에 나온 4.0.0 뒤 첫 기능 업데이트이고, 3.8.0은 3.x 줄에 몇 년 동안 쌓여 있던 수정을 한꺼번에 내보낸 버전입니다.

공식 블로그는 3.8.0을 두고 다시 돌아오는 게 아니라 떠나보내는 릴리스라고 적었습니다. 3.8.0이 3.x의 마지막 기능 릴리스이고, 앞으로 3.x는 중요한 보안 수정과 버그 수정만 받는다는 뜻입니다.

그래서 이번 릴리스에서 할 일은 두 갈래로 나뉩니다. 바로 4.x로 옮길 수 있으면 옮기고, 당장 어렵다면 3.x 안에서라도 3.8.0으로 올려 두는 것입니다. 아래에서 둘 다 순서대로 적었습니다.1

jQuery 버전 확인 방법: 콘솔 한 줄과 npm

지금 쓰는 버전부터 봐야 합니다. 브라우저에서 사이트를 열고 개발자 도구 콘솔에 jQuery.fn.jquery를 치면 버전 문자열이 나옵니다. $가 jQuery를 가리키는 페이지라면 $.fn.jquery도 같습니다.

npm으로 받아 쓰는 프로젝트라면 프로젝트 폴더에서 npm ls jquery를 치면 실제로 깔린 버전이 보입니다. 다른 패키지가 jQuery를 따로 끌어온 경우도 같이 나와서, 버전이 두 개 섞여 있는지 볼 때도 쓸 만합니다.

npm 레지스트리 기준으로는 기본 설치 버전(latest)이 4.1.0이고, 3.x 줄의 최신을 가리키는 v3-latest 태그는 3.8.0입니다. 그냥 npm install jquery를 치면 4.1.0이 들어온다는 뜻이라, 3.x에 머물 프로젝트는 버전을 꼭 적어야 합니다.

버전별 배포 날짜를 보면 3.x에 얼마나 오래 새 릴리스가 없었는지도 보입니다. 3.8.0 바로 앞 버전인 3.7.1은 2023년 8월 28일에 나왔습니다. 3.7.1을 쓰고 있다면 2년 넘게 묵은 버전을 쓰고 있는 셈입니다.3,1

두 버전 공통 수정: 선택자 ReDoS와 콜백 방식

두 버전에 똑같이 들어간 수정이 있어서, 어느 줄을 쓰든 이번에 올릴 이유가 됩니다. 가장 중요한 건 선택자 처리에 쓰는 정규식 문제입니다.

jQuery가 선택자 안의 이름을 읽을 때 쓰던 정규식이, 16진수 이스케이프가 길게 이어지다 잘못된 문자로 끝나는 문자열을 만나면 계산을 끝없이 되풀이할 수 있었습니다. 이런 공격을 ReDoS라고 부르는데, 그 사이 페이지가 멈춥니다.

공식 블로그는 속성 선택자 안에 이런 문자열이 들어가는 경우를 예로 들었습니다. 사용자가 입력한 값을 선택자 문자열에 그대로 붙여 쓰는 코드가 있다면 특히 신경 써야 할 부분입니다. 이번 버전은 규격대로 숫자와 16진수 문자를 걸러서 이 문제를 없앴습니다.

사용자 정의 AJAX 전송 방식을 직접 만들어 쓰는 경우에는 완료 콜백을 객체 하나로 받을 수 있게 됐습니다. 기존처럼 인자 네 개를 순서대로 넘기는 방식도 그대로 됩니다. 오래된 IE와 레거시 엣지에서 드물게 나던 오류를 막는 수정도 함께 들어갔습니다.1

jQuery 3.8.0에서 바뀐 것: hidden until-found와 지원 중단 예고

3.8.0에만 들어간 변화 중 눈에 보이는 건 hidden 속성입니다. hidden은 원래 켜고 끄는 값만 있었는데, 지금은 페이지 안 찾기로 접힌 내용을 펼칠 수 있게 해 주는 until-found 값이 생겼습니다.

3.x는 이 값을 일반 켜짐으로 바꿔 버렸습니다. 노드에서 jsdom으로 같은 코드를 세 버전에 돌려 보니 3.7.1은 hidden="hidden"으로 바꿔 넣었고, 3.8.0과 4.1.0은 until-found를 그대로 남겼습니다.

3.8.0은 4.0에서 지워진 API 두 묶음에 공식으로 지원 중단 표시를 달았습니다. jQuery 객체의 push, sort, splice와 jQuery.expr[":"], jQuery.expr.filters입니다. 앞의 셋은 원래 내부용이었고, 뒤의 둘은 jQuery.expr.pseudos로 바꾸면 됩니다.

지원 중단 표시가 붙었다는 건 Migrate 플러그인이 이 API를 쓰는 코드를 찾아 경고해 줄 수 있다는 뜻입니다. 4.x로 넘어가기 전에 3.8.0에서 미리 고쳐 둘 수 있게 해 둔 것입니다.1

jQuery 4.1.0에서 바뀐 것: responseURL과 querySelectorAll

4.1.0의 새 기능 중 바로 쓸 만한 건 AJAX 응답 객체의 responseURL입니다. 서버가 요청을 다른 주소로 넘겼을 때 최종으로 도착한 주소를 알려 줍니다. 요즘 브라우저의 일반 요청에서만 채워지고, IE 11과 스크립트, JSONP 요청에서는 비어 있습니다.

formAssociated를 켠 사용자 정의 요소도 이제 serialize()와 serializeArray()에 제대로 들어갑니다. 웹 컴포넌트로 만든 입력란이 폼 전송 값에서 빠지던 문제를 겪었다면 이 버전에서 풀립니다.

내부에서는 요소를 찾을 때 getElementsByTagName과 getElementsByClassName을 더 쓰지 않고 querySelectorAll 하나로 통일했습니다.

공식 블로그는 요즘 브라우저에서 속도가 같거나 더 빠르다고 설명합니다. 문서 조각에서 > 같은 기호로 시작하는 선택자가 안 먹던 오래된 버그도 같이 고쳐졌습니다.

중복 요소를 지우는 jQuery.uniqueSort도 다시 짰습니다. 배열을 한 번만 훑으며 정리하는 방식이라, 연결되지 않은 요소가 많을 때 더 빨리 끝난다고 합니다. 결과와 순서는 그대로입니다.1

jQuery 3.x에서 4.x로 업그레이드하는 순서: Migrate 4

공식 업그레이드 안내가 권하는 순서는 단순합니다. 페이지의 jQuery를 최신 4.x로 바꾸고, 바로 뒤에 압축하지 않은 jQuery Migrate 4.x를 붙인 다음, 페이지를 써 보면서 콘솔에 뜨는 경고를 하나씩 고칩니다.

Migrate는 지워진 기능을 잠시 되살려 주면서 어디서 그 기능을 쓰는지 알려 줍니다. 4.1.0 위에 Migrate 4.0.2를 얹고 지워진 $.trim을 불러 보니, 결과는 그대로 나오고 String.prototype.trim을 쓰라는 경고가 함께 찍혔습니다.

경고를 다 고쳤으면 Migrate를 빼고 다시 돌려 봅니다. 그때도 잘 돌아가야 업그레이드가 끝난 것입니다. 압축한 Migrate 파일은 경고를 거의 남기지 않으니 고치는 동안에는 꼭 압축하지 않은 파일을 씁니다.

Migrate 없이 4.1.0만 올리면 이런 API가 그냥 없어집니다. 같은 테스트에서 3.7.1과 3.8.0은 $.fn.push와 $.trim이 함수로 남아 있었고, 4.1.0에서는 둘 다 undefined였습니다. 이 함수를 쓰는 플러그인이 있으면 그 자리에서 오류가 납니다.2,4

jQuery 4로 바꿀 때 자주 걸리는 것

코드에서 가장 자주 걸리는 건 4.0에서 지워진 유틸리티 함수입니다. jQuery.trim, isArray, isFunction, parseJSON, now, type 같은 것들인데, 대부분 Array.isArray나 JSON.parse, Date.now처럼 자바스크립트 기본 기능으로 바꾸면 됩니다.

브라우저 지원 범위도 줄었습니다. 4.x는 IE 11만 지원하고 IE 10 이하와 크로뮴 이전 엣지는 빠졌습니다. 아직 IE 10 이하를 지원해야 하는 사이트라면 3.x에 남아야 하고, 그때는 Migrate 3.x로 최신 3.x까지만 맞추면 됩니다.

CSS 값에 단위를 자동으로 붙이는 동작도 바뀌었습니다. 이제는 px가 꼭 필요한 일부 속성에만 붙으니, css("width", 100)처럼 숫자만 넘기던 코드는 결과를 다시 보는 게 좋습니다. 처음부터 "100px"처럼 단위를 붙여 쓰면 걱정할 일이 없습니다.

jQuery UI를 같이 쓴다면 1.13.3 이상이어야 합니다. 노드에서 jsdom과 함께 쓰는 테스트 코드는 4.0부터 jquery/factory 진입점을 쓰도록 바뀌었으니, 테스트가 갑자기 깨지면 이 부분부터 보면 됩니다. slim 빌드에서는 Deferred와 콜백, 큐 모듈이 빠졌습니다.2

jQuery 3.x에 남을 때 할 일

레거시 플러그인이 많아서 지금 4.x로 못 옮기는 사이트도 있습니다. 그렇다면 3.8.0으로라도 올리는 게 맞습니다. 위에서 본 선택자 정규식 수정이 3.8.0에 들어 있고, 앞으로 3.x에는 중요한 수정만 나옵니다.

npm으로 관리한다면 npm install jquery@3.8.0처럼 버전을 적어 설치합니다. 버전 없이 설치하면 4.1.0이 들어오니 package.json에 적힌 범위가 ^3.7.1처럼 3.x에 묶여 있는지도 함께 봅니다.

3.8.0에 Migrate 3.x를 붙여 두면 4.0에서 없어질 API를 어디서 쓰는지 미리 알 수 있습니다. 당장 옮기지 않더라도 경고를 하나씩 줄여 두면 나중에 4.x로 넘어가는 일이 훨씬 가벼워집니다.1,2,3
