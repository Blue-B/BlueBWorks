GitHub Copilot Dynamic Workflows 공개 — 멀티에이전트 절차를 코드로 고정한다

GitHub가 Copilot CLI·Copilot 앱·Copilot SDK에 Dynamic Workflows를 공개 프리뷰로 추가했다. 자동화 단계와 여러 에이전트를 코드로 조합해 순차·병렬 실행, 구조화된 결과 전달, 검토 체크포인트까지 반복 가능한 절차로 만들 수 있다.

요약
  • 에이전트와 도구 호출을 코드 기반 워크플로로 조합한다.
  • 순차·병렬 실행과 구조화된 결과 전달을 지원한다.
  • Copilot CLI에서는 실험 기능을 별도로 켜야 한다.
덧붙임

멀티에이전트의 약점은 모델 수가 아니라 절차가 재현되지 않는 데서 자주 생긴다. Dynamic Workflows는 에이전트에게 전부 맡기는 대신 순서·병렬성·검증 단계를 코드로 고정한다. 장애 조사나 릴리스 점검처럼 ‘누가 어떤 순서로 무엇을 확인했는가’가 중요한 작업에 특히 맞는 방향이다.

무엇이 나왔나

Dynamic Workflow는 작업 절차를 프로그램으로 정의하고 그 안에 명령·도구·외부 서비스 호출과 하나 이상의 에이전트 작업을 섞는 기능이다. 단계는 순차 또는 병렬로 실행할 수 있고, 앞 단계의 구조화된 결과를 다음 단계로 넘기거나 여러 에이전트가 서로의 결과를 검증하게 할 수도 있다.

개발자에게 왜 중요한가

멀티에이전트 작업을 매번 프롬프트의 자율 판단에 맡기지 않고 재현 가능한 코드 흐름으로 고정할 수 있다는 점이 핵심이다. 릴리스 점검, 대규모 코드 리뷰, 장애 조사처럼 단계·검증·중단 조건이 명확해야 하는 작업에서 실행 과정을 관찰하고 다시 쓰기 쉬워진다.

직접 써볼 때 알아둘 점

현재 공개 프리뷰이며 모든 Copilot 플랜에서 제공된다. Copilot 앱에서는 바로 사용할 수 있지만 Copilot CLI에서는 최신 버전에서 `--experimental` 또는 `/experimental on`으로 실험 기능을 켜야 하고, 단순한 질문이나 작은 수정은 일반 채팅이 더 적합하다.
