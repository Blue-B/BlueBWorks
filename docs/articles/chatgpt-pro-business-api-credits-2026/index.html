챗지피티 API 크레딧 혜택, 구독과 API 결제는 여전히 따로

OpenAI가 10월 28일(UTC) 개발자 X 계정과 공식 유튜브 채널에 챗지피티 Pro와 Business 구독자를 위한 API 크레딧 혜택을 올렸다. 한국 시간으로는 10월 29일 오전이다. 조건을 갖춘 구독자는 매달 최대 500달러어치 API 크레딧을 받아 앱이나 에이전트를 만드는 데 쓸 수 있다.

이 말만 보면 챗지피티를 쓰는 사람은 누구나 API를 공짜로 쓸 수 있을 것 같지만 그렇지 않다. 공식 도움말은 대상 구독을 본인이 소유한 API 조직 하나에 연결해야 크레딧이 들어온다고 설명한다. 구독이 있다고 잔액이 저절로 생기는 구조가 아니라서, 연결을 마친 뒤 실제로 발급됐는지까지 봐야 한다.

여기서 API 조직은 API 키와 프로젝트, 사용량, 결제를 묶어 두는 계정 단위다. 이번 크레딧은 연결한 조직의 API 비용에만 쓰이고, 챗지피티 대화 한도나 로그인해서 쓰는 Codex 한도는 그대로다. 구독료 청구와 API 청구도 합쳐지지 않는다. 바뀐 건 구독 혜택으로 API 비용 일부를 메울 수 있게 됐다는 점 하나다.

이 글은 공식 도움말과 개발자 가이드를 다시 읽고, Plus 계정으로 챗지피티 설정과 API 플랫폼 결제 화면에 직접 들어가 본 결과를 함께 정리했다. 크레딧을 실제로 받아 본 후기는 아니고, 신청 버튼이나 결제 버튼은 누르지 않았다. 위의 공식 영상과 아래 X 게시물이 발표 원문이다.

Pro와 Business 요금제별 API 크레딧 금액

Pro는 가입한 등급에 따라 금액이 갈린다. 월 100달러 등급은 100달러, 200달러 등급은 200달러, 500달러 등급은 500달러를 한 결제 기간 기준으로 받는다. 이 금액은 API 사용에만 쓰는 크레딧이라 환급이나 현금 지급과는 다르다.

Business는 사람마다 500달러씩 받는 방식이 아니다. 유료 Standard 좌석마다 20달러, Premium 좌석마다 100달러를 더한 금액을 워크스페이스가 함께 쓰고, 월 500달러가 상한이다. 도움말 예시대로 Standard 5명과 Premium 3명이면 100달러에 300달러를 더해 월 400달러가 된다. Standard 10명과 Premium 4명이면 계산상 600달러지만 상한에 걸려 500달러다.

연간 요금을 미리 낸 Business 워크스페이스는 일 년 치를 한 번에 받고, 연간 결제 주기마다 최대 6,000달러다. 월 500달러에 연간 6,000달러가 따로 붙는 게 아니니 두 숫자를 더해서 계산하면 안 된다.

Plus와 무료 체험은 대상이 아니다. 개발자 가이드는 무료로 제공된 구독도 제외한다고 적어 두었고, Enterprise와 Edu, 예전 Codex 좌석이 포함된다는 내용도 공식 문서에는 없다. Plus를 쓰면서 최대 500달러라는 숫자만 봤다면 기대를 접는 편이 맞다. 크레딧 때문에 더 비싼 요금제로 옮길지는 실제로 API를 얼마나 쓸지 따져 보고 정할 일이다.

Plus 계정으로 챗지피티 결제 설정에 들어가 본 화면

Pro 사용자가 챗지피티 쪽에서 시작할 때 공식 도움말이 안내하는 경로는 설정의 결제 메뉴다. 왼쪽 아래 프로필 메뉴에서 설정을 열면 개인 항목 아래쪽에 결제가 있다. Business는 대상 워크스페이스를 고른 뒤 워크스페이스 결제 설정이나 관리 콘솔에서 시작한다.

10월 30일 Plus 계정으로 같은 경로에 들어가 보니 결제 화면에는 현재 플랜, 거래 내역, 결제 정보, 결제 수단만 있었고 API 크레딧 항목은 없었다. Plus가 대상이 아니라는 공식 설명과 맞는 결과다. 캡처에서는 거래 내역과 카드, 주소가 들어 있는 오른쪽 영역을 통째로 가렸다.

Pro 계정이라면 이 결제 화면에서 API 크레딧 혜택을 찾아 연결을 시작한다고 도움말은 설명한다. 순서는 혜택 찾기, 크레딧을 받을 API 조직 확인, 확정이다. Pro 화면은 직접 확인하지 못했으니 버튼 이름이나 위치는 계정에 따라 조금 다를 수 있다. 메뉴가 안 보인다면 지금 로그인한 계정이 구독을 소유한 계정인지부터 보면 된다.

API 플랫폼 Billing과 Credit grants에서 신청과 발급 확인하기

API 플랫폼에서 시작하는 방법도 있다. 챗지피티 구독과 같은 이메일로 API 플랫폼에 로그인하고, 연결할 API 조직을 고른 뒤 Billing에서 혜택을 찾는다. 이어서 대상 구독이나 Business 워크스페이스를 선택하고 내용을 확인하면 연결이 끝난다고 도움말은 적고 있다.

직접 들어가 보면 왼쪽 메뉴 Billing 안에 Overview, Payment methods, Billing history, Credit grants, Preferences, Promotions 탭이 나란히 있다. Plus 계정에 딸린 Personal 조직에서는 Overview에 API 크레딧 혜택 안내가 따로 보이지 않았다. 적격 구독이 있는 계정이라면 여기서 혜택을 찾게 된다.

신청보다 더 중요한 건 발급 확인이다. Credit grants 탭에는 받은 크레딧마다 받은 날짜, 상태, 잔액, 만료일이 한 줄씩 나온다. 연결을 마쳤는데 이 표에 새 줄이 없으면 크레딧이 들어온 게 아니다. 도움말의 문제 해결 항목도 연결은 됐는데 지급 내역이 안 보이면 선택한 조직부터 확인하라고 안내한다.

신청 전에 볼 조건은 세 가지다. 유료 구독이 7일 이상 이어졌는지, 챗지피티와 API 계정의 이메일이 같은지, 신청하는 사람이 구독이나 워크스페이스와 크레딧을 받을 API 조직 양쪽의 소유자인지다. Business 멤버나 관리자 역할만으로는 부족하다.

한 구독은 API 조직 하나에만 연결되고, 조직도 이런 연결을 하나만 가질 수 있다. 그래서 앱을 실제로 돌릴 조직을 처음에 제대로 고르는 게 중요하다. 연결을 바꾸려면 지원팀에 문의해야 하고, 바꾼다고 크레딧이 옮겨지거나 더 나온다는 보장은 없다.

API를 처음 쓰는 사람도 같은 이메일의 Personal 조직에 연결할 수 있고, 챗지피티 쪽에서 신청하기 전에 API 온보딩을 다 마칠 필요는 없다고 한다. 메뉴가 안 보이면 플랜과 구독 기간, 고른 워크스페이스, 이메일을 먼저 확인한다. 국가나 제공 대상 그룹에 따라 늦게 보일 수도 있어서 한국의 모든 계정에 바로 보인다고 단정하기는 어렵다.

API 크레딧 사용 범위와 Codex 제외 조건

개발자 가이드에 따르면 연결 조직으로 청구되는 Responses, Agents, Decisions, GPT-Live와 Realtime, Images 비용에 크레딧이 쓰인다. 웹 검색과 파일 검색, Code Interpreter 같은 내장 도구 비용, Agents의 OpenAI 호스팅 샌드박스와 저장 비용도 들어간다. 텍스트 출력에만 쓰는 크레딧은 아니라는 뜻이다.

반대로 API 키로 쓰는 Codex에는 적용되지 않는다고 두 공식 문서가 모두 적어 두었다. 로그인해서 쓰는 Codex나 챗지피티의 사용 한도도 늘지 않는다. 코딩 에이전트를 더 오래 돌리려고 신청을 고민 중이라면 어떤 제품을 어떤 인증 방식으로 쓰는지부터 나눠 봐야 한다.

Business 팀원이 이 크레딧을 쓰려면 API 조직과 프로젝트 권한을 따로 받아야 한다. 챗지피티 좌석이 있다고 API 권한이 자동으로 생기지는 않는다. 요청에는 연결 조직에 속한 프로젝트의 API 키를 쓰고, 키는 공개 저장소나 브라우저 코드에 넣지 말고 서버 쪽 환경 변수 같은 곳에 두는 편이 안전하다.

API 크레딧 만료일과 다 쓴 뒤의 결제 흐름

첫 지급액은 현재 결제 기간에서 남은 날만큼 일할 계산된다. 200달러 등급이라도 기간 중간에 신청하면 처음에는 200달러보다 적게 들어올 수 있다. 정확한 금액은 신청 화면과 Credit grants에 찍힌 숫자로 확인해야 한다.

한 번 연결하면 구독이 유지되는 동안 갱신 때마다 다시 지급되므로 매달 신청할 필요는 없다. 월 크레딧은 결제 주기가 끝나면 사라지고 다음 달로 넘어가지 않는다. 연간 선불 Business도 그 주기가 끝나면 남은 금액이 만료된다. 몇 달 모아 두었다가 큰 작업에 쓰는 적립금으로 생각하면 곤란하다.

이 크레딧을 쓰는 데 결제 수단을 새로 등록할 필요는 없다. 이미 사 둔 API 크레딧이 있으면 무료 크레딧이 먼저 쓰이고, 다 쓰면 구매한 잔액으로 이어진다. 남은 크레딧이 전혀 없으면 요청이 HTTP 429와 credit_balance_exhausted 오류로 실패한다. 429는 요청 속도 제한에서도 나오는 코드라 오류 이름까지 같이 봐야 원인을 가릴 수 있다.

Usage 화면은 API 사용량과 비용 기록을 보여 주지만, 크레딧을 뺀 뒤 실제로 청구된 금액과 같지는 않다. 자동 충전을 켜 둔 조직이라면 충전 기준과 월 한도를 한 번 확인해 두는 게 좋다. 이 글을 쓰면서 계정의 구독, 결제, 충전 설정은 하나도 바꾸지 않았다. 혜택 내용은 10월 30일 공식 문서 기준이고 앞으로 바뀌거나 끝날 수 있다.
