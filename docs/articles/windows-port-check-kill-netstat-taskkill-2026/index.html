윈도우 포트 확인과 포트 죽이기, netstat 과 taskkill

윈도우에서 3000번이나 8080번 포트가 이미 사용 중이라고 나올 때 어떤 프로그램이 잡고 있는지 찾아 끄는 방법입니다. cmd 에서는 netstat -ano 와 taskkill, PowerShell 에서는 Get-NetTCPConnection 과 Stop-Process 를 쓰는데, PowerShell 쪽은 PID 를 넘기는 방식을 잘못 쓰면 오류만 나고 포트가 그대로 남습니다.

요약
  • netstat -ano | findstr :3000 으로 포트를 잡은 PID 를 찾고, tasklist 로 어떤 프로그램인지 본 다음 taskkill /PID 번호 /F 로 끕니다.
  • findstr :3000 은 30001번 같은 다른 포트도 함께 걸러 냅니다. LISTENING 줄만 남기고 포트 번호 뒤 공백까지 붙여 찾아야 정확합니다.
  • PowerShell 에서 OwningProcess 숫자를 Stop-Process 로 바로 파이프하면 바인딩 오류가 나고 포트는 그대로입니다. Stop-Process -Id 뒤에 괄호로 넘기거나 Get-Process 를 거칩니다.
  • PID 가 4 로 나오면 Windows 의 System 프로세스입니다. 끄는 대상이 아니니 내 서버의 포트 번호를 바꾸는 편이 빠릅니다.

윈도우 포트 확인, 이미 사용 중 오류에서 시작합니다

개발 서버를 띄우다 보면 address already in use 오류를 자주 만납니다. 앞서 띄운 서버를 창만 닫고 끝냈거나, 다른 프로그램이 같은 포트를 먼저 잡고 있을 때 나옵니다.

Windows 11 Pro 에 연습용 node 서버를 3000번 포트로 하나 띄워 두고 같은 명령을 한 번 더 실행해 봤습니다. 두 번째 서버는 EADDRINUSE 오류를 남기고 바로 꺼졌습니다.

이럴 때 할 일은 두 가지입니다. 그 포트를 누가 잡고 있는지 찾고, 내가 띄운 것이 맞으면 끄는 것입니다. cmd 에서는 netstat 과 taskkill 두 줄이면 끝납니다.

PowerShell 로 한 줄에 끝내려다 오류만 나고 포트가 그대로 남은 일도 있었습니다. 왜 그런지, 실제로 통한 명령은 무엇인지도 뒤에 적었습니다.1

netstat -ano 로 포트를 잡은 PID 찾기

cmd 나 PowerShell 어느 쪽에서든 netstat -ano 를 실행하면 지금 열린 TCP 연결과 대기 중인 포트가 전부 나옵니다. -a 는 대기 중인 포트까지, -n 은 주소를 숫자로, -o 는 연결마다 PID 를 붙여 줍니다.

목록이 길어서 보통 findstr 로 원하는 포트만 거릅니다. 3000번으로 거르자 두 줄이 나왔습니다. 0.0.0.0 은 IPv4, [::] 는 IPv6 주소이고 같은 서버가 두 주소에서 기다리는 모습입니다.

맨 끝 숫자 3148 이 그 서버의 PID 입니다. 포트를 붙잡고 기다리는 쪽은 상태가 LISTENING 인 줄이고, 브라우저가 붙어 있으면 ESTABLISHED 줄도 보이는데 PID 는 LISTENING 줄 것을 보면 됩니다.

-b 를 더하면 실행 파일 이름까지 보여 주지만 Microsoft 문서에 따르면 시간이 오래 걸리고 권한이 부족하면 실패합니다. 일반 창이라면 PID 를 먼저 찾고 이름은 tasklist 로 보는 편이 빠릅니다.

명령이 낯설다면 찾은 PID 를 들고 작업 관리자로 가도 됩니다. netstat 문서도 -o 로 얻은 PID 로 작업 관리자에서 해당 프로그램을 찾을 수 있다고 안내합니다. 다만 포트 번호 자체는 작업 관리자에 나오지 않으니 PID 는 netstat 으로 먼저 구해야 합니다.1

사용중인 포트 죽이기는 taskkill /PID 번호 /F

PID 만으로는 무슨 프로그램인지 알 수 없으니 끄기 전에 tasklist 로 이름을 봅니다. tasklist /FI "PID eq 3148" 을 실행하자 node.exe 가 메모리 36,840K 를 쓰고 있다고 나왔습니다.

내가 띄운 개발 서버가 맞으니 taskkill /PID 3148 /F 로 끕니다. /F 는 강제로 끝내라는 옵션이고, 실행하자 SUCCESS 와 함께 프로세스가 끝났다는 메시지가 나왔습니다.

같은 netstat 명령을 다시 돌리면 아무 줄도 나오지 않습니다. 3000번 포트가 비었다는 뜻이고, 이제 서버를 다시 띄우면 오류 없이 올라옵니다.

/F 없이 실행하면 메시지가 Sent termination signal 로 바뀝니다. 종료 신호만 보낸다는 뜻인데 이번 node 서버는 그 신호만으로 꺼졌습니다. 신호를 받고도 남아 있으면 그때 /F 를 붙입니다.

이미 꺼진 PID 에 다시 taskkill 을 보내면 not found 오류가 납니다. 자식 프로세스까지 같이 끝내려면 /T 를 붙이면 되고, 지정한 프로세스가 시작한 자식들까지 함께 정리됩니다.

이름으로 한꺼번에 끄는 /IM node.exe 도 있습니다. 다만 다른 창에서 돌던 node 까지 모두 꺼지기 때문에 포트 하나만 비우려는 상황이라면 PID 로 끄는 쪽이 안전합니다.2

findstr :3000 이 30001번 포트까지 잡는 문제

포트 번호를 그대로 findstr 에 넣으면 그 숫자로 시작하는 다른 포트도 같이 걸립니다. 3000번과 30001번에 서버를 하나씩 띄우고 findstr :3000 으로 거르자 네 줄이 나왔습니다.

그중 두 줄은 PID 가 다른 30001번 서버였습니다. 맨 끝 숫자만 보고 taskkill 을 했다면 엉뚱한 서버를 끌 뻔했습니다. 포트 번호 뒤에 공백을 붙이고 LISTENING 줄만 남기면 3000번만 나옵니다.

findstr 은 따옴표 안의 공백을 검색어 구분으로 읽기 때문에, 공백까지 한 덩어리로 찾으려면 /C: 를 앞에 붙여야 합니다. 아래 두 번째 명령이 그렇게 거른 결과입니다.

PID 가 4 로 나오는 포트도 있습니다. 이 PC 에서는 445번과 5357번이 그랬고, tasklist 로 보면 이름이 System 입니다. Windows 자체라 끄는 대상이 아니니 내 서버 포트를 바꾸는 편이 빠릅니다.

Stop-Process 문서도 프로세스를 끄면 그 프로세스에 기대는 다른 프로세스와 서비스가 함께 멈출 수 있고, 심하면 Windows 가 멈출 수 있다고 적고 있습니다. 낯선 이름이면 끄기 전에 한 번 더 봅니다.1,3

PowerShell 포트 확인은 Get-NetTCPConnection

PowerShell 에서는 Get-NetTCPConnection 이 netstat 자리를 대신합니다. -LocalPort 로 포트를, -State Listen 으로 대기 중인 연결만 고르면 OwningProcess 칸에 PID 가 나옵니다.

문자열을 거르는 방식이 아니라 포트 번호로 고르는 방식이라 30001번이 섞이지 않습니다. 앞에서 겪은 findstr 문제를 신경 쓰지 않아도 되는 점이 가장 편했습니다.

-State 는 Listen, Established, TimeWait 처럼 상태 이름을 받습니다. -State 를 빼면 그 포트로 오간 연결까지 모두 나오니, 포트를 잡은 프로그램만 찾을 때는 Listen 을 넣어 두는 편이 깔끔합니다.

netstat 은 0.0.0.0 과 [::] 두 줄을 보여 줬는데 Get-NetTCPConnection 은 :: 한 줄만 보여 줬습니다. 줄 수는 달라도 PID 는 똑같이 3148 이었습니다.

PowerShell 7.6 과 Windows 에 기본으로 들어 있는 Windows PowerShell 5.1 양쪽에서 같은 명령이 돌아갔습니다. PID 를 알면 Get-Process -Id 로 프로세스 이름과 시작 시각까지 볼 수 있어 여러 개가 떠 있을 때 고르기 쉽습니다.4

Stop-Process 로 PID 숫자를 파이프하면 오류가 납니다

한 줄로 끝내려고 OwningProcess 를 꺼내 Stop-Process 로 바로 넘겨 봤습니다. 8080번에 서버를 띄워 둔 상태였는데, 돌아온 것은 입력 개체를 어떤 매개변수에도 묶을 수 없다는 오류였습니다.

다시 조회해 보니 8080번은 여전히 Listen 상태였습니다. 인터넷에 돌아다니는 한 줄 명령 중에 이 형태가 꽤 있어서, 오류 메시지를 못 보고 넘어가면 포트가 왜 안 비는지 한참 헤매게 됩니다.

이유는 Stop-Process 문서의 -Id 항목에 있습니다. -Id 는 파이프로 들어온 값을 그대로 받지 않고, 들어온 개체에 Id 라는 속성이 있을 때만 그 값을 받습니다.

-ExpandProperty 로 꺼낸 PID 는 그냥 숫자라 Id 속성이 없습니다. 파이프로 그대로 받을 수 있는 건 프로세스 개체뿐이고, 문서의 입력 항목에도 프로세스 개체를 파이프할 수 있다고만 나옵니다.3,4

PowerShell 에서 포트 죽이기, 실제로 통한 명령

숫자를 파이프 대신 -Id 뒤 괄호 안에서 구해 넘기자 8080번 서버가 바로 꺼졌습니다. -PassThru 를 붙이면 끈 프로세스를 다시 보여 주는데 HasExited 가 True 로 나왔습니다.

그다음 8080번을 다시 조회했을 때 Listen 줄은 하나도 없었습니다. 결과가 여러 줄이면 같은 PID 가 겹쳐 나올 수 있어서, 한 번씩만 넘기도록 Select-Object -Unique 를 붙여 두었습니다.

프로세스 개체를 만들어 넘기는 방법도 됩니다. Get-Process -Id 로 얻은 개체는 파이프로 Stop-Process 에 그대로 넘어갑니다. 3000번 서버를 이 방식으로 끄자 node 프로세스가 정상적으로 내려갔습니다.

끄기 직전에 한 번 더 묻게 하고 싶다면 -Confirm 을 붙입니다. 문서 예시처럼 프로세스 이름과 PID 를 함께 보여 주고, 그 질문에 답해야 끝냅니다.

다른 사용자 계정이 띄운 프로세스는 일반 창에서 꺼지지 않을 수 있습니다. Stop-Process 문서는 현재 사용자 소유가 아닌 프로세스를 끄려면 PowerShell 을 관리자 권한으로 열어야 한다고 안내합니다.3,4

포트 번호만 바꿔 쓰는 명령 묶음

아래 3000 자리에 자기 포트 번호만 바꿔 넣으면 됩니다. cmd 와 PowerShell 중 익숙한 쪽 하나만 기억해도 충분하고, 어느 쪽이든 끄기 전에 프로그램 이름을 보는 순서는 같습니다.

3000번과 8080번만의 이야기는 아닙니다. 5173, 8000처럼 개발 도구마다 기본으로 쓰는 포트가 다를 뿐, 어느 번호든 PID 를 찾고 이름을 본 뒤 끄는 순서는 똑같습니다.

끄자마자 같은 포트가 다시 잡힌다면 PID 가 바뀌었는지 봅니다. 새 PID 라면 무언가가 서버를 다시 띄우고 있다는 뜻이니, 그 프로그램을 먼저 멈춘 다음 포트를 비워야 같은 일이 반복되지 않습니다.1,2,3,4
