# BlueBWorks

**작게 만들고, 직접 써보고, 쓸 이유를 증명하는 프로젝트 작업실.**

최신 기술과 실제 사용자 문제에서 출발해, 하루 두 개의 독립적으로 실행 가능한 작은 제품을 만드는 것을 목표로 합니다. 프로젝트 수를 채우기 위한 복제 앱이나 문서뿐인 결과물은 만들지 않습니다.

## 운영

- **개발:** 한국시간 오전 8시·오후 7시 전후에 각각 한 프로젝트를 목표로 조사 → 선정 → 구현 → 테스트 → 작업 브랜치 push → main 반영 확인 → 결과 보고를 진행합니다. 실행 시작 시각이며 완료 시각 보장은 아닙니다.
- **보관:** 코드는 `projects/<project-name>/`, 개발 기록은 `reports/YYYY-MM/YYYY-MM-DD-am.md` 또는 `pm.md`에 저장합니다.
- **반영:** 소유자 승인에 따라 검증한 결과를 비공개 `main`까지 반영합니다. `daily/YYYY-MM-DD-am|pm` 브랜치와 PR은 작업 기록이며 미병합 PR에서 멈추지 않습니다. 실제 main 파일을 다시 조회한 뒤 완료를 보고합니다.
- **범위:** private을 유지하며 외부 배포·릴리즈·유료 서비스·홍보·권한 변경은 별도 승인 대상입니다. 필수 검사·리뷰·보호 규칙을 우회하지 않습니다.
- **정직한 기록:** 실행 실패·승인 대기·미완성은 그대로 기록합니다. 형식 검사 통과를 제품 기능 검증으로 대신하지 않으며 직접 검증과 원격 CI 결과를 구분합니다.

## 프로젝트

### [ScopeDiff](projects/scopediff/)

MCP 업데이트 전후의 도구 목록을 로컬에서 비교하는 프로토타입입니다. 도구 추가·삭제, 설명·힌트·필수 입력 변경을 확인하고 JSON/Markdown 보고서를 저장합니다. 실제 권한이나 보안을 판정하는 프로그램은 아닙니다.

[수동 시험 보고서](reports/2026-09/2026-09-26-am.md) · [병합된 PR #1](https://github.com/Blue-B/BlueBWorks/pull/1) · [main 반영 커밋](https://github.com/Blue-B/BlueBWorks/commit/a02c2002b5bbc6f3934c873db4fc584a90860a73)

병합 전 전달 파일 11개의 Git blob 해시가 PR 소스와 일치함을 확인하고 프로젝트 테스트 63개와 단일 HTML 빌드를 다시 실행했습니다. 모두 정상 종료했습니다. 원격 CI는 테스트 단계 시작 전 실패 상태로 확인되어 성공으로 표시하지 않습니다. 이 수동 반영은 예약 무인 실행의 성공을 증명하지 않습니다.

초기 저장소 구성과 운영 문서 갱신은 신규 프로젝트로 세지 않습니다. 다른 결과물은 [프로젝트 폴더](projects/)와 [작업 Pull Request](https://github.com/Blue-B/BlueBWorks/pulls)에서 확인할 수 있습니다.

## 선정 기준

실제 사용자가 반복해서 겪는 문제를 해결하고, 기존 대안 최소 두 개와 비교해 구체적인 차이가 있어야 합니다. 사용자가 자신의 입력으로 핵심 기능을 체험할 수 있어야 하며, 오류 처리와 재현 가능한 테스트를 포함해야 합니다. 최신성·화제성·수익화 가능성은 조사할 대상이지 성공을 보장하는 근거가 아닙니다.

## 저장소 검사

검사기 자체는 Python 3.11 이상에서 외부 패키지 없이 실행합니다. 각 프로젝트가 선언한 검사에는 해당 실행 환경이 추가로 필요합니다.

```sh
python3 -m unittest discover -s tests -v
python3 automation/check.py
python3 automation/check.py --run
```

첫 번째는 저장소 검증기의 회귀 테스트, 두 번째는 프로젝트 등록 정보 검사, 세 번째는 각 프로젝트에 선언된 실제 테스트·빌드 명령 실행입니다. 프로젝트가 없으면 제품 기능을 검증했다고 표시하지 않습니다. 프로젝트 실행 명령은 저장소 코드를 먼저 검토한 뒤 사용하세요.
