# BlueBWorks

**작게 만들고, 직접 써보고, 쓸 이유를 증명하는 프로젝트 작업실.**

최신 기술과 실제 사용자 문제에서 출발해, 하루 두 개의 독립적으로 실행 가능한 작은 제품을 만드는 것을 목표로 합니다. 프로젝트 수를 채우기 위한 복제 앱이나 문서뿐인 결과물은 만들지 않습니다.

## 운영

- **개발:** 한국시간 오전 8시·오후 7시 전후에 각각 한 프로젝트를 목표로 조사 → 선정 → 구현 → 테스트 → 작업 브랜치 반영 → 결과 보고를 진행합니다. 실행 시작 시각이며 완료 시각 보장은 아닙니다.
- **보관:** 코드는 `projects/<project-name>/`, 개발 기록은 `reports/YYYY-MM/YYYY-MM-DD-am.md` 또는 `pm.md`에 저장합니다.
- **검토:** 결과는 `daily/YYYY-MM-DD-am|pm` 브랜치와 Pull Request로 확인합니다. 기본 브랜치 자동 병합, 유료 서비스 사용, 외부 배포와 홍보 게시물 발행은 기본 범위에 포함하지 않습니다.
- **정직한 기록:** 실행 실패·승인 대기·미완성은 그대로 기록합니다. 형식 검사 통과를 제품 기능 검증으로 대신하지 않습니다.

## 프로젝트

아직 등록된 제품이 없습니다. 초기 저장소 구성과 자동 검증 코드는 제품 두 개로 세지 않습니다. 실제 결과물은 [프로젝트 폴더](projects/)와 [작업 Pull Request](https://github.com/Blue-B/BlueBWorks/pulls)에서 확인할 수 있습니다.

## 선정 기준

실제 사용자가 반복해서 겪는 문제를 해결하고, 기존 대안 최소 두 개와 비교해 구체적인 차이가 있어야 합니다. 사용자가 자신의 입력으로 핵심 기능을 체험할 수 있어야 하며, 오류 처리와 재현 가능한 테스트를 포함해야 합니다. 최신성·화제성·수익화 가능성은 조사할 대상이지 성공을 보장하는 근거가 아닙니다.

## 저장소 검사

Python 3.11 이상에서 외부 패키지 없이 실행합니다.

```sh
python3 -m unittest discover -s tests -v
python3 automation/check.py
python3 automation/check.py --run
```

첫 번째는 저장소 검증기의 회귀 테스트, 두 번째는 프로젝트 등록 정보 검사, 세 번째는 각 프로젝트에 선언된 실제 테스트·빌드 명령 실행입니다. 프로젝트가 없으면 제품 기능을 검증했다고 표시하지 않습니다. 프로젝트 실행 명령은 저장소 코드를 먼저 검토한 뒤 사용하세요.
